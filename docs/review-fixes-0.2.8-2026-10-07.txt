수정 범위

1. [P1] 마지막 저장 이후 문서 전환 중 입력 유실: SDK + 프론트 수정

- SDK에 acquireInputLock()을 추가했다. 내부 입력 차단의 응답을 기다린 뒤 반환한다.
- 잠금 중 새 execute/replace/applyPreset을 거절한다. 이미 시작한 명령은 마지막 저장에서 기다린다.
- save()가 끝나도 호스트의 전환 잠금은 유지한다. 중첩 잠금은 각각 해제하며 새 편집 세션에는 전달하지 않는다.
- DocumentEditSession은 마지막 저장 전에 SDK 잠금을 확보하고, lease 해제와 문서 전환까지 유지한다.
- lease 해제 직전·응답 직후 문서/편집 세션/권한과 저장 상태를 재확인한다.
- 저장이나 release 실패 시 잠금을 회수하고 현재 편집기를 유지한다. 편집권 재확인 후 재시도할 수 있다.
- 새 문서 열기와 에이전트 작업 요청의 공통 handoff에 적용했다.

2. [P1] HWPX readonly/busy에서 포커스된 내부 입력창 변경: SDK + 엔진 수정

- EngineViewProps.inputBlocked와 EditorSession.setInputBlocked()로 내부 입력 차단 계약을 추가했다.
- HWPX는 iframe 내부의 inert/textarea readonly와 capture 단계 입력·조합·붙여넣기·드롭 차단을 함께 적용한다.
- iframe 생성 때부터 초기 잠금 상태를 전달한다. 변경 시 native 명령의 적용 응답을 기다린다.
- 잠금 직전까지 이미 표시된 한글 조합은 native undo history에 한 번 확정한다.
- 잠금 뒤 도착한 input/compositionend가 문서를 바꾸지 않도록 하며, 해제 후 다시 편집할 수 있다.
- 허용된 이전 SDK 명령의 내부 이벤트와 새 사용자 이벤트를 구분해 저장 대기 중 명령을 유실하지 않는다.
- 저장/flushDraft/preset 직렬화 전에도 내부 입력 차단을 기다리고, 완료 뒤 남은 readonly/전환 잠금을 존중한다.
- DOCX도 native surface의 inert와 포커스 해제를 명시적으로 적용한다.
- 고정 RHWP 소스 파일은 직접 수정하지 않았다. 기존 build-time 플러그인에 조합 확정 메서드를 추가하고 자산을 재생성했다.

3. [P2] 늦은 저장 알림이 다른 문서의 dirty 상태를 해제: 프론트 수정

- 실제 저장 bytes/version은 완료 시 해당 원본에 먼저 반영한다.
- 파일 목록 갱신을 기다리기 전에 문서/owner/편집 세션/generation을 캡처한다.
- await 후 동일한 문서와 마운트된 편집 세션인지 재검증한다.
- unmount되거나 새 문서로 교체된 경우 이전 알림으로 onSaved(false)를 호출하지 않는다.
- 같은 세션이어도 새 미저장 내용이나 대기 명령이 있으면 dirty 해제 알림을 생략한다.
