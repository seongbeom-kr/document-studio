1. 검색 조건과 치환 대상 연결: 해결 확인

코드
SearchSession이 검색 조건·문서/세션·revision과 요청 세대를 함께 관리한다.
query/matchCase/wholeWord 변경은 기존 결과와 선택을 즉시 무효화한다.
늦은 검색 응답은 현재 token과 맞는 경우만 반영한다.
선택 완료도 현재 token과 현재 결과 안의 match ID를 확인한다.
DocumentEditor는 편집 세션 ID까지 포함한 documentKey를 도구 패널에 전달한다.

직접 시험
- 새로운 검색이 먼저 완료된 뒤 이전 검색 응답이 늦게 도착해도 결과를 덮지 않았다.
- 검색어 변경 후 이전 선택 치환 버튼이 비활성화됐다.

실제 DOCX
검증 3개 검색 → 표 셀의 검증 선택 → 검색어를 한국어로 변경했다.
변경 전 선택 치환 버튼은 활성 상태였다.
변경 후 버튼은 비활성, 기존 검증 결과는 0개, 문서 텍스트는 원래와 동일했다.

실제 HWPX
검증 1개 검색 → 결과 선택 완료 → 검색어를 한국어로 변경했다.
이전 치환 대상이 비활성화되고 기존 결과가 제거됐다.
이전 리뷰처럼 화면의 새 검색어 아래에서 옛 단어를 바꾸는 상태가 유지되지 않았다.

2. 실행 중 preset의 읽기 전용/대상 변경: 해결 확인

코드
후속 명령 전후에 readOnly, 권한 세대, 문서/세션, namespace, 원본 및 지원 상태를 검사한다.
명령 배열을 복사하여 호출자가 실행 중 변경해도 실행 계획이 바뀌지 않게 한다.
PresetApplicationError의 completedCommands/totalCommands로 적용된 단계를 알려준다.

직접 실패 주입 시험
- 첫 명령 응답 지연 중 readOnly=true: 후속 명령 없이 거절.
- readOnly=true가 된 뒤 false로 복구: 이전 preset은 계속하지 않고 거절.
- 첫 명령 응답 지연 중 새 원본 전달: 후속 명령 없이 거절.
- 실행 중 호출자 명령 배열의 alignCenter를 bold로 변경: 원래 복사한 alignCenter가 실행.

예외에서 completedCommands=1, totalCommands=2도 확인했다.
이미 전달되고 완료된 첫 명령의 서식은 남을 수 있다. 이는 전체 롤백을 구현했다는 뜻은 아니다.
읽기 전용 전환은 실제 사용자의 권한을 바꾸지 않고, 실제 SDK 컴포넌트에 호스트 prop 변경을 주입해 확인했다.

3. DOCX 강조색 선택: 해결 확인

코드
DOCX 어댑터가 Word 강조색 16개의 valueChoices/valueSchema.enum을 제공한다.
글자색과 강조색 입력이 분리됐다. DOCX 강조색은 제한 팔레트를 사용한다.

직접 시험
- 자유 글자색을 #245f56으로 바꿔도 강조색은 노랑으로 분리되어 동작했다.
- 팔레트에 허용되지 않은 값을 입력 이벤트로 주입하면 적용 버튼은 비활성화됐다.
- 허용된 노랑은 실제 DOCX 어댑터를 통해 오류 없이 실행됐다.

실제 화면
- DOCX의 강조색 선택지 16개를 확인했다.
- 노란 강조색 적용 후 현재 강조색 #ffff00 상태를 확인했다.
- Undo 후 저장했고 텍스트는 동일했으며 잘못된 원본 변경 경고도 없었다.
- HWPX는 강조색 input type=color를 유지했다.
  이번 실제 화면에서는 HWPX 임의 RGB의 적용·XML 결과까지 검사한 것은 아니다.

증거
- 02-docx-highlight-palette.png
- tool-ux-current.test.tsx의 색상 시험 2개

4. 여전히 남은 사용성 개선

우선순위 높음: 한 번 적용한 보고서 서식을 한 번 Undo로 복구
실제 0.2.5 HWPX의 검증 단어를 선택했을 때 원래는 10pt·양쪽 정렬이었다.
보고서 제목을 한 번 적용한 뒤 Undo 한 번을 누르면 16pt·가운데 정렬이 남았다.
총 세 번 Undo해야 10pt·양쪽 정렬로 돌아왔다.
저장본을 다시 열고 같은 검증 단어를 선택해 10pt, 가운데=false, 양쪽=true를 확인했다.

이번 변경은 복합 작업의 안전한 중단을 구현했으며 단일 Undo나 전체 원자적 롤백을 구현한 것은 아니다.
사용자가 한 작업으로 인식하는 preset은 한 번 Undo로 복구하는 것이 좋다.
중단 시 일부 서식이 남는다는 안내와 복구 방법도 사용자 관점에서 명확해야 한다.
증거: 04-hwpx-preset-single-undo-still-partial.png

우선순위 중간: 수치 표시와 자동화 입력
numeric 입력은 내부 변환 수치를 그대로 표시하는 구조가 유지돼 있다.
표시 정밀도와 내부 정밀도를 분리하고 혼합/미확인 값의 의미를 쉽게 보여주는 개선이 남는다.
업무 자동화도 공통 추가 인수 필드를 유지한다. 기준일·인원수·변환 조건 등 기능별 이름과 예시가 필요하다.
이 두 항목은 현재 코드 확인에 따른 미완료 사항이며 이번에 모든 기능을 실제 화면으로 재검증한 결과는 아니다.

그림 비율 유지·삽입 위치 안내, 복잡한 실무 문서의 서식 보존 검증도 별도 과제다.
