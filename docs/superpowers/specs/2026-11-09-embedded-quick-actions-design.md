# 플랫폼 내 빠른 작업 UI 설계안

상태는 검토용 초안이다. 기준 화면은 dev.gridone.net에서 채팅 옆에 HWP 문서를 열고 상단 `빠른 작업`을 누른 상태다. SDK 작업본 `7e4f33b`와 프론트 `dev`의 `82058b92d`에서 호출 경로를 확인했다.

## 사용 흐름

플랫폼의 기존 `빠른 작업` 버튼을 누르면 좁은 편집 영역에서는 문서 아래에 작은 패널이 열린다. 문서와 저장 표시가 함께 남는다. 패널을 열면 `날짜·기간`을 기본으로 선택하고 `서식`, `원고 정리`로 바꿀 수 있다. 각 작업의 입력만 보인다.

```text
┌──────────── 채팅 ────────────┬──────────── 문서 편집 ────────────┐
│                              │ 파일명 · 미리보기 · 기존 도구 모음 │
│                              ├──────────────────────────────────┤
│                              │ 문서 본문                        │
│                              │               커서 ▏            │
│                              ├──────────────────────────────────┤
│                              │ 빠른 작업        문서 도구   ×   │
│                              │ 날짜·기간    서식    원고 정리    │
│                              │ [오늘] [이번 주] [다음 주] [더보기]│
│                              │ 2026. 11. 9.(월)         [적용]  │
│                              │ 커서 위치에 삽입                  │
│                              ├──────────────────────────────────┤
│                              │ 기존 편집 상태 · 저장 표시        │
└──────────────────────────────┴──────────────────────────────────┘
```

- `오늘`을 누르면 결과와 `적용`이 패널 안에 즉시 나타난다. 한 번 더 `적용`을 눌러 문서를 편집한다. 커서에서는 `커서 위치에 삽입`, 텍스트가 선택된 경우에는 선택 문구와 `선택한 내용 교체`를 보여준다. 서식은 `현재 문단에 서식 적용` 또는 `선택한 범위에 서식 적용`으로 구분하고, 실제 적용되는 서식만 보여준다.
- `더보기`에 어제·내일·이번 달·다음 달·올해·내년과 날짜 설정을 둔다. 사용자 기준일, 오늘로 갱신, 주간 범위, 날짜 표시 및 공휴일 안내를 같은 곳에서 제공한다. 날짜 결과는 사용자가 선택한 기존 기준일·형식으로 계산한다.
- `서식`에서는 SDK 및 호스트가 제공한 프리셋을 보여준다. 선택한 서식의 변경 항목은 결과 영역에서 확인하고, 긴 목록은 별도로 스크롤할 수 있다.
- `원고 정리`에서는 기존 입력과 `원고 정리 미리보기`를 사용한다. 결과 영역에는 변경 줄 수와 정리된 원고의 첫 줄 일부를 보여준다. 전체 결과와 줄별 변경은 스크롤 영역에서 확인한다.
- 패널의 `문서 도구`를 누르면 기존 `문단` 탭과 전체 도구 탭이 열린다. 좁은 화면의 빠른 작업에서 전체 도구 탭, 크기 슬라이더와 확대 버튼 자리를 줄인다. 독립 편집기에서는 기존 전체 도구 탭으로도 이동할 수 있다.

## 배치와 상호작용

기존 도구 영역에 빠른 작업 전용 내용을 넣는 방식을 제안한다. 커서 옆 팝오버는 가깝지만 플랫폼 편집 영역의 폭과 HWP iframe 경계를 함께 다뤄야 한다. 화면 전체를 쓰는 방식은 긴 원고에 공간을 주지만 적용할 문서를 가린다. 기존 도구 영역은 문서와 결과를 함께 두고, 호스트가 이미 연결한 도구 진입점도 활용할 수 있다.

- **내장 배치.** 편집기 컨테이너 폭 1100px 이하에서는 문서 아래에 배치하고, 더 넓으면 기존 옆 배치를 사용한다. 패널은 문서 본문을 덮지 않는 레이아웃 안에 놓인다. 좁은 배치의 패널 높이 상한은 작업 영역 높이의 45%와 220px 중 작은 값이다. 편집기 본문과 도구가 공유하는 작업 영역의 크기로 판단한다.
- **결과 고정.** 길어지는 입력·목록·변경 상세에만 패널 스크롤을 둔다. 날짜 결과와 `적용`은 그 스크롤 바깥에 두고, 폭이 좁으면 줄바꿈한다. 320×400px 이상인 작업 영역에서 기본 날짜 버튼과 날짜 결과·적용을 스크롤 없이 확인할 수 있는지 검증한다. 그보다 작은 경우에도 내용 스크롤로 입력에 접근하고 문서를 덮는 자동 확대는 사용하지 않는다.
- **호스트 배치.** 플랫폼은 지금처럼 `context.openTools("quick")`을 호출한다. `ui.containers.tools`를 직접 지정한 앱에서는 SDK가 해당 컨테이너 위치·높이를 맡기고 패널 안의 입력·결과 구조를 제공한다. 기존 SDK 테마 토큰을 사용한다.
- **선택 보호.** 날짜·서식 버튼은 미리보기만 만든다. 선택 범위나 문서 버전이 바뀌면 결과에 `문서 또는 선택 범위가 바뀌었습니다. 작업을 다시 선택해 주세요.`를 표시하고 `적용`을 잠근다. 같은 항목을 다시 누르면 새 대상의 미리보기를 만든다. 읽기 전용에서는 미리보기를 볼 수 있고 적용은 잠긴다.
- **입력과 결과의 수명.** 날짜 설정이나 원고를 변경하거나 작업 종류를 바꾸면 이전 미리보기를 지운다. 도구를 닫거나 다른 문서·편집 세션으로 이동해도 이전 미리보기는 이어서 쓰지 않는다. 기존 세션의 날짜 설정·원고와 복구 안내는 유지한다. 정상 상태에서 입력 내려받기와 보관 안내는 `입력 관리`에 두고, 복구·보관 오류는 바로 보여준다.
- **키보드와 적용.** 미리보기에서 포커스를 유지하고 결과 요약을 보조 기술에 알린다. `Tab`으로 적용을 선택할 수 있다. 적용 중 중복 실행을 막고 성공·실패를 같은 위치에 표시한다. 적용 버튼이 사라질 때 그 버튼에 포커스가 있었다면 미리보기를 만든 버튼으로 돌려준다. `Esc`로 패널을 닫으면 실제 진입 버튼으로 돌아간다. 적용 후 편집기에서 한 번 되돌릴 수 있으며, 서버 저장은 기존 저장 동작을 따른다.

작업 범위는 SDK React UI와 배치다. 기존 `QuickActionTools`의 세션 저장 방식, 코어의 미리보기·적용 검증, 프리셋·날짜 계산과 플랫폼의 공개 연결 방식에 맞춰 구현한다. 검증은 DOCX·HWPX 브라우저 시험과 플랫폼 HWP 화면의 확인으로 나눈다.
