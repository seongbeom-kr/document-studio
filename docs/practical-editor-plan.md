# 실사용 문서 편집 SDK 개발 계획

HWPX·DOCX를 기존 React 앱 안에서 편집하는 공개 SDK를 개발합니다. 자체 코드의 Apache-2.0 라이선스를 유지하고 RHWP 0.8.6 MIT, EigenPal core/react 2.25.0 Apache-2.0의 무료 기능을 기준으로 기능·파일 보존·소비 앱 검증을 함께 수행합니다. 기능을 연결했다는 사실과 다양한 파일에서 호환성이 검증됐다는 사실은 구분합니다.

## 요구 기능과 근거

[최신 범정부 오피스 공식 자료](https://sotong.go.kr/front/board/boardContentsView.do?board_id=240&contents_id=7bf5da6228d146fcade014ede52bb129&menu_id=606)의 2026-08-04 공개판과 첨부된 91쪽 가이드북을 확인했습니다. 실행 파일·코드·기관 서식을 복사하지 않고 문단·보고서·금액·날짜·표 데이터·명단·차트 기능군을 자체 API와 UI로 구현합니다. [기능군 대응표](government-office-reference.md)에 완료 범위와 남은 기능을 기록합니다. 개별 1,000여 단축키 전체와 동등하다고 표시하지 않습니다.

엔진의 공개 기능은 [RHWP 고정 소스](https://github.com/edwardkim/rhwp/tree/e8800c8def63449808a4092798442652ed460552), [EigenPal 기능표](https://www.docx-editor.dev/docs/2.x/word-fidelity), 설치된 고정 버전의 타입·실행 결과로 확인합니다. 댓글 작성·변경 추적·협업·상용 Editor API/PDF 변환 모듈은 무료 라이선스와 구분합니다. 무료 엔진의 미지원 기능이나 stub은 활성 명령으로 노출하지 않습니다.

## 구현 순서

1. 기능 계약·검증·preset과 라이선스 목록을 추가합니다. 임의 엔진 명령을 무제한 실행하는 API 대신 지원·입력 범위가 있는 명령을 제공합니다.
2. DOCX와 HWPX의 문단·표·그림·페이지·검색 경로를 구현하고 공통 도구 패널을 연결합니다. 형식별 무료 도구는 엔진 확장 패널로 접근하도록 합니다.
3. 문서 위치와 revision을 함께 확인하는 에이전트 조회·선택·치환을 구현합니다. 오류나 엔진 거절을 성공으로 반환하지 않습니다.
4. 다양한 자체 제작 업무 유형 corpus와 UI·파일 보존·고장 주입 시험을 추가합니다. 검사 결과에 따라 구현을 수정합니다.
5. 타입·전체 테스트·패키지 build·라이선스 검사·독립 소비 앱 검증을 수행하고 기능별 실제 지원표와 공개 절차를 갱신합니다.

## 테스트 조건

Chrome·Edge에서 두 형식의 실제 편집·저장·재열기를 검사합니다. 현재 합성 corpus는 한국어 보고서, 목록·표·그림, 문단/페이지 경계, DOCX 중첩/병합 표, 혼합 언어·서식, 긴 문서와 손상 ZIP입니다. 본문·미디어·머리말/꼬리말·구조 보존을 확인했습니다. 임의 외부 관계·모든 미지원 객체와 미수정 ZIP parts 전체의 보존 검사는 후속 확대 항목이며 완료했다고 표시하지 않습니다.

Microsoft Word 독립 읽기는 설치된 환경에서 실행합니다. 실제 한컴 한글과 물리 IME는 환경이 제공될 때의 별도 검증 gate로 기록하며 CDP 조합 입력이나 같은 엔진 재열기로 대체 완료했다고 쓰지 않습니다. 운영 샌드박스의 인증·lease·동기화는 SDK 계약과 모의 서버 검사, 실제 서비스 검사로 구분합니다.

## 배포 기준

라이선스가 확인되지 않은 실행 파일·폰트·샘플은 배포하지 않습니다. 직접·전이 의존성과 번들 JS/WASM의 출처·라이선스·고지를 기록하고 미확인/금지 의존성은 release gate에서 실패시킵니다. 고정 버전의 permissive 의존성도 요구되는 원본 고지를 함께 제공합니다. npm/GitHub 공개는 준비한 배포물을 실제 공개 대상에 게시하는 별도 작업입니다.
