이전 지적의 현재 상태

1. 새 문서 생성의 409
lease release를 일반 신규 업로드보다 먼저 실행하도록 withHandoff를 연결했다.
실패 시 기존 편집권 재확보와 입력 잠금 유지/해제 처리가 추가됐다.
코드와 프론트 집중 시험으로 수정 반영은 확인했으나, 실제 서버에서 최종 패키지의
DOCX/HWPX 생성·실패 복구·재열기는 검증 대기다.

2. 닫기 확인창에서 새 SDK 쓰기 수락
공통 assertNewMutation에 모달 상태가 포함됐다.
0.2.8에서 실패한 동일 재현 시험은 0.2.9에서 통과했다.

3. 미리보기 결과를 고치면 생성 버튼이 설명 없이 꺼짐
문서형 결과는 읽기 전용이고 생성 기준이 원본 입력임을 안내한다.
원본 입력 수정 버튼의 실제 포커스 이동을 확인했다.

4. 편집 종료 후 자동화 입력 소실
opt-in한 실제 Chrome IndexedDB에 일반 크기의 입력을 보관하고,
편집기 닫기/재열기에서 기능 선택과 원본 입력이 동일하게 복구됐다.
다만 아래 새 P2의 큰 입력 경계는 남아 있다.

5. 키보드 탭 동작 누락
ArrowRight로 표에서 그림으로 선택/포커스가 이동했다.
선택 탭만 tabindex=0이며 tab/tabpanel 연결도 확인했다.
Escape로 도구를 닫았을 때 열기 버튼으로 포커스가 돌아왔다.

6. 좁은 도구 작업 공간
1366x768 독립 host에서 도구 크게 보기를 사용했다.
입력은 유지됐고 native 문서는 제거되지 않았으며 확대 중 본문은 inert였다.
실제 샌드박스 모달/브랜드 레이아웃과의 조합은 서버 복구 후 추가 검증이 필요하다.

새 P2의 정확한 범위

AutomationSession.put/flush에는 읽기와 같은 길이 검증이 없다.
reader는 input/argument/delimiter length <= 1_000_000을 요구한다.
신규 경계 시험은 1,000,000자 대조는 통과하고 1,000,001자 round trip은 실패했다.
store 대역에서 저장 성공 상태까지 확인한 뒤 재열기가 거절되는 것을 검증했다.
실제 UI textarea도 최대 길이 제한이 없었다.

대용량 Chrome IndexedDB나 실제 서버 저장 시험을 했다는 뜻은 아니다.
자동 삭제/영구 자료 손상도 확인한 것이 아니다. 저장한 자료를 SDK가 다시 복구하지 못하는
읽기/쓰기 계약 결함이며 다른 정상 기능의 초안 복구에도 영향을 줄 수 있다.
상세 근거와 수정 완료 기준은 적대적 리뷰에 기록했다.

독립 브라우저에서 추가 확인한 것

- DOCX 보고서 생성 후 제목·본문·표 셀을 실제 엔진의 public readDocument로 확인.
- HWPX 보고서 생성 후 첫 제목, 두 번째 본문, 표, 표 뒤 문단이 분리된 것을 확인.
- 이전 HWPX 제목/본문 병합과 앞쪽 빈 문단 문제는 이 자료에서 보이지 않음.
- 읽기 전용 결과, 원본 입력 포커스, 도구 확대/복귀, 입력 보관/재열기.

독립 host의 문서 저장/생성 후 열기는 메모리 구현이다.
자동화 초안만 실제 IndexedDB를 사용한다.
실제 샌드박스의 인증·BFF·lease·신규 업로드 성공과 혼동하지 않는다.
