Document Studio 실서비스 UI/UX 리뷰
검토일: 2026-10-05, 약 20:08~20:21 KST
대상: https://sblim.dev.gridone.net/sandbox-agent
관련 코드 위치: D:\dev\document-studio
검토 목적: 문서 편집 기능의 존재보다 실제 사용자가 쉽고 편하게 쓸 수 있는지 평가

1. 종합 판단

현재 화면은 기본 기능을 사용할 수 있는 베타 수준이다.
아직 'UI/UX가 정말 좋은 문서 편집기'라고 평가하기는 어렵다.

파일 열기, 한글 문구 입력, 저장, 재열기 흐름은 시험용 DOCX와 HWPX에서 작동했다.
공통 도구와 저장 상태 표시, 변경사항을 버리기 전 경고도 좋은 기반이다.
하지만 문서에 집중할 공간이 부족하고, 상세 도구의 값과 현재 문서 상태가
일치하지 않는 경우가 있으며, 확장 도구를 열면 제품의 언어와 디자인이 바뀐다.
사용자가 안심하고 오래 편집할 수 있도록 화면 구조와 상태 표현을 먼저 정리해야 한다.

이 평가는 실서비스 화면을 직접 조작한 전문가 관찰이다.
실제 사용자 집단을 대상으로 한 사용성 조사나 정량적인 만족도 결과는 아니다.

2. 직접 확인한 범위

- 사용 중인 Chrome의 실제 화면: 1920×889
- 추가 화면 크기: 1366×768; 검토 후 화면 크기 설정 복원
- '문서 테스트' 작업에 별도 시험 파일 두 개 업로드
  SDK-live-review-20261005.docx
  SDK-live-review-20261005.hwpx
- 두 문서에 ' · UIUX 확인' 문구를 추가하고 저장한 뒤 다시 편집 화면에서 확인
- DOCX: 본문과 표 유지 확인, 제목 문단 행간 150%로 변경, 저장본 재열기
- DOCX: 저장하지 않고 파일 목록으로 이동할 때의 경고 및 '계속 편집' 확인
- DOCX: '검증' 검색 시 결과 2개 및 결과 문맥 표시 확인
- 두 형식의 기본 화면, 크게 보기, 상세 문단 도구, 형식별 확장 도구 확인
- HWPX: 저장 후 닫기, 재열기 후 수정 문구 확인; 미리보기 r2 확인
- 기존 사용자 문서는 수정하지 않았음. 시험 파일 두 개는 작업 공간에 남겨 둠.
- 제품 코드 수정 없이 리뷰 기록과 화면 증거만 추가함.

복잡한 실무 문서 전체, 모바일, 실제 한글 IME 조합 과정, Word/한글에서의
최종 출력 동일성까지 검증한 결과는 아니다.

3. 개선 사항: 우선순위 순

[P1] 편집 도구가 본문 공간을 지나치게 차지한다

관찰:
1920×889 기본 화면에서는 전역 메뉴, 작업 목록, 채팅, 문서가 동시에 보인다.
문서 패널은 약 840px 폭이고, 파일 헤더와 편집기 헤더에 파일명이 두 번 나온다.
상태 안내와 두 줄로 접히는 공통 도구까지 있어서 본문 영역이 줄어든다.
상세 문단 도구를 열면 DOCX 본문 표시 공간은 약 200px 높이로 줄어든다.
1366×768에서는 채팅과 작업 목록을 숨겨 폭을 확보하는 처리가 잘 되어 있다.
그럼에도 HWPX 상세 문단 도구를 펼친 상태의 iframe 높이는 실측 123px였다.
이는 문서 전체 배치나 표를 보면서 설정을 바꾸기에 부족하다.

사용자 영향:
문서의 결과를 보려면 도구를 닫고, 값을 바꾸려면 다시 펼치는 행동이 반복된다.
긴 문서나 표 중심의 문서에서는 설정과 결과를 동시에 보기 더 어렵다.

권장 변경:
편집 진입 시 문서가 중심이 되는 화면 구성을 기본으로 제공한다.
큰 제목 헤더와 파일명 중복을 줄이고 상태 안내는 짧은 한 줄로 합친다.
상세 도구는 오른쪽 속성 패널 또는 팝오버로 배치하고, 높이 제한과 독립 스크롤을 둔다.
반복적인 문단·표 편집을 위해 '크게 보기'를 매번 찾아야 하는 부담을 줄인다.

완료 기준:
1366×768에서도 상세 도구를 열고 본문 여러 문단이나 표를 동시에 확인할 수 있어야 한다.
본문을 직접 조작하는 작업과 설정 변경 사이에 도구를 접는 행동이 필수가 아니어야 한다.

증거: 01-docx-default.png, 04-docx-tools-default.png, 12-hwpx-1366-tools.png

[P1] 상세 설정값이 현재 문서 상태와 자동으로 맞춰지지 않는다

관찰:
DOCX 문단의 공통 행간 도구를 150%로 바꿨다.
동시에 열려 있던 상세 문단 패널의 '행간 값'은 1.6을 유지했다.
'현재 문단 값 읽기'를 누르자 1.5로 바뀌었다.
즉, 같은 화면에 같은 속성을 나타내는 값이 서로 다르게 표시됐다.

사용자 영향:
상세 설정의 숫자가 현재 문단의 값인지, 미리 정해진 입력값인지 구분하기 어렵다.
다른 항목 하나만 바꾸려고 해도 기존 설정을 잘못 판단할 수 있다.
문서 서식 변경 결과를 신뢰하기 어렵게 만드는 문제다.

권장 변경:
선택 위치 이동과 공통 도구의 변경에 상세 패널도 자동으로 반응하게 한다.
자동 반영이 어렵다면 '현재 값'과 '적용할 값'을 명확히 나누고 미조회 상태를 표시한다.
여러 문단의 값이 다르면 임의 숫자 대신 '혼합' 상태를 표시한다.
사용자가 바꾼 속성만 적용할 수 있게 한다.

완료 기준:
공통 도구에서 150%를 선택하면 상세 패널도 즉시 1.5를 표시해야 한다.
별도의 '읽기' 버튼을 누르지 않아도 현재 설정을 정확히 판단할 수 있어야 한다.

[P2] 저장과 다운로드의 의미가 여러 위치에 흩어져 있다

관찰:
외부 파일 헤더에 '원본 다운로드', 편집기 내부에 '다운로드'와 '저장',
화면 아래에 '저장 후 닫기'가 동시에 있다.
저장 상태는 표시되지만 저장되는 위치와 다운로드 대상의 차이는 버튼 주변에 설명되지 않는다.
'원본'이 최초 업로드 파일을 뜻하는지, 마지막 저장본을 뜻하는지도 문구만으로는 모호하다.
변경사항을 남긴 채 파일 목록으로 이동하면 '계속 편집'과 '변경 버리기'만 제공된다.
이 경고에는 '저장하고 이동' 선택지가 없다.

사용자 영향:
내 PC에 받는 동작과 작업 공간 파일에 반영하는 동작을 혼동할 수 있다.
작업을 마치기 위해 어느 저장 버튼을 선택해야 하는지 한 번 더 판단해야 한다.

권장 변경:
대표 동작을 '작업 공간에 저장'으로 분명히 표현하고 마지막 저장 시점을 표시한다.
다운로드는 대상에 맞게 '현재 편집본 다운로드' 또는 '최신 저장본 다운로드'로 구분한다.
닫기는 '편집 완료' 등 사용자의 목적에 맞춰 표현하고 저장 여부를 처리한다.
이동 경고에 '저장하고 이동 / 변경 버리기 / 계속 편집' 선택지를 제공한다.

완료 기준:
버튼만 보고도 파일이 PC로 내려오는지, 작업 공간에 저장되는지 판단할 수 있어야 한다.
수정 후 다른 파일로 이동하려는 흐름을 경고창 안에서 바로 완료할 수 있어야 한다.

증거: 01-docx-default.png, 05-unsaved-dialog.png

[P2] 형식별 확장 도구를 열면 언어와 디자인이 크게 달라진다

관찰:
두 형식의 기본 도구는 같은 구조로 제공된다.
그러나 DOCX 확장 도구는 'File / Format / Insert / Page setup' 영어 메뉴를 보여준다.
HWPX 확장 도구는 별도의 한글 데스크톱 앱 형태 메뉴와 도구 상자를 보여준다.
HWPX에서는 글꼴, 크기, 행간, 정렬 도구가 외부 공통 도구와 내부 도구에 중복된다.
회색 배경, 눈금자, 아이콘과 버튼의 모양도 DOCX 화면과 다르다.

사용자 영향:
기본 도구와 확장 도구 중 어느 쪽에서 작업해야 하는지 학습이 필요하다.
파일 형식에 따라 같은 기능을 다른 언어와 위치에서 다시 찾아야 한다.
제품 하나 안에서 편집기의 사용 방식이 바뀌는 느낌을 준다.

권장 변경:
사용자가 자주 쓰는 작업은 공통 도구로 충분히 수행할 수 있게 통합한다.
형식별 확장 기능은 공통 도구에서 제공하지 않는 기능에 집중한다.
DOCX 메뉴를 한국어로 제공하고, 핵심 용어·선택 상태·아이콘·간격을 맞춘다.
'형식별 확장 도구'보다 '고급 기능'처럼 목적을 설명하는 이름을 검토한다.

완료 기준:
글꼴·정렬·페이지 설정·표 편집은 형식이 달라도 같은 경로와 용어로 찾을 수 있어야 한다.
확장 도구를 열었을 때 같은 기능의 도구가 두 벌 보이는 상황을 줄여야 한다.

증거: 06-docx-native-menu.png, 09-hwpx-native-tools.png

[P2] 비활성 도구의 이유와 사용할 조건이 설명되지 않는다

관찰:
HWPX 문단 도구의 '들여쓰기 늘리기', '들여쓰기 줄이기', '문단 부호'가 비활성이다.
표 밖에서 표 탭을 열면 셀 분할, 행·열 편집, 셀 배경 등 여러 기능이 비활성이다.
확인한 비활성 버튼에는 title이나 aria-describedby를 통한 설명도 없었다.

사용자 영향:
현재 선택 때문에 사용할 수 없는지, 문서 형식이 지원하지 않는지 알기 어렵다.
표 안을 클릭해야 하는 사용자에게 다음 행동을 안내하지 못한다.

권장 변경:
표 도구에는 '표 안의 셀을 먼저 선택하세요' 안내를 제공한다.
형식에서 지원하지 않는 도구는 이유를 짧게 설명하거나 관련 메뉴에서 제외한다.
비활성의 원인을 색상만으로 전달하지 않는다.

완료 기준:
사용자가 현재 상태에서 할 수 있는 행동을 문구로 확인할 수 있어야 한다.
선택 부족과 형식 미지원이 구분되어야 한다.

증거: 12-hwpx-1366-tools.png 및 비활성 버튼 DOM 속성 확인

[P2] 편집을 시작하고 검색·속성 도구를 찾는 경로가 덜 명확하다

관찰:
파일 목록에서 문서를 누르면 미리보기가 열리고, 별도 '편집' 버튼을 눌러야 편집을 시작한다.
편집 화면에서 자주 쓰는 찾기는 '편집 도구 → 찾기와 바꾸기' 안에 있다.
같은 탭 줄에 글자·문단·표·페이지와 보고서 서식·업무 자동화가 함께 배치된다.
'현재 작업이 끝나면 편집할 수 있습니다' 안내가 짧게 나타난 후 편집기가 준비됐다.

사용자 영향:
단순 조회에는 안전한 구조지만, 반복적으로 문서를 수정하는 사용자는 경로가 길어진다.
기본 편집 기능과 별도의 업무 기능이 섞여 도구를 훑는 비용이 커진다.
대기 안내만으로는 준비 중인지, 에이전트 작업이 진행 중인지 판단하기 어렵다.

권장 변경:
파일 메뉴에 직접 편집 진입 경로를 제공하고, 미리보기의 편집 버튼을 분명하게 강조한다.
찾기는 항상 접근 가능한 위치에 두고 지원하는 단축키를 함께 안내한다.
보고서 서식·업무 자동화는 목적이 다른 도구이므로 별도 위치를 검토한다.
대기 상태는 실제 이유와 다음 상태를 설명한다. 예: '편집 권한을 준비하고 있습니다'.

완료 기준:
처음 사용하는 사람이 편집 시작과 문서 내 검색 위치를 쉽게 찾을 수 있어야 한다.
현재 대기 원인을 구체적으로 이해할 수 있어야 한다.

4. 유지하면 좋은 부분

- DOCX/HWPX 공통 기본 도구: 형식을 바꿔도 핵심 도구 위치가 유지된다.
- 크게 보기: 주변 채팅과 탐색 UI가 사라져 집중하기 좋다.
- 1366×768 대응: 작업 목록과 채팅을 숨겨 문서 폭을 확보한다.
- 저장 상태: '저장하지 않은 변경사항 / 저장 중 / 모든 변경사항 저장됨'이 구분된다.
- 변경 보호: 파일 목록으로 나갈 때 손실 위험을 문장으로 안내한다.
- 검색 결과: 일치한 단어를 강조한 문맥과 검색 개수를 표시한다.
- 파일 목록: 검색, 정렬, 끌어놓기 업로드 안내가 있다.
- 버전 이력 진입점: 이전 버전으로 접근하는 경로가 보인다.
  이번 리뷰에서는 실제 이전 버전 복원 동작까지 실행하지 않았다.

5. 권장 개선 순서

첫째, 문서 본문 공간 확보: 중복 헤더 축소, 상세 도구 배치 변경, 집중 편집 진입 개선.
둘째, 화면 상태의 신뢰성: 상세 설정 자동 동기화, 혼합 상태, 비활성 이유 안내.
셋째, 저장 흐름 정리: 저장 대상 명시, 다운로드 명칭 구분, 이동 경고에서 저장 가능하게 개선.
넷째, 형식 간 일관성: 확장 도구 한국어화, 중복 제거, 공통 작업의 경로 통일.
