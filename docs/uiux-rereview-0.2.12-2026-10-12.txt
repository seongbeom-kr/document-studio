1. 사용자 경험의 변화

이전 버전에서 사용자가 추측해야 했던 부분들이 명시됐다. 삽입이 평문이라는
버튼 설명, 구조를 유지해 새 문서를 만든다는 구분, 제목 기반 파일명과 현재
형식/저장 위치, 명찰/명패의 내용 초안 범위는 실질적인 개선이다.
기능이 계산/표 정리/문서 작성/행사 자료/그림으로 묶이고 검색 입력도 생겼다.
14px 입력 글자와 13px 도움말, 현재 적용 대상, 도구 크기 조절도 반영됐다.

여전히 입력을 수정하며 구조 미리보기와 본문을 대조하는 흐름은 다듬어야 한다.
에이전트 작업의 제안/적용/저장/결과 확인이 UI에 이어지는 경험도 아직 없다.
이번에는 실제 LLM 요청을 보내지 않았다. 문서 SDK의 기능과 실제 에이전트
업무가 완료된 상태를 같은 것으로 취급하지 않는다.

실제 HWPX 화면:

- 기능 메뉴는 다섯 목적별 그룹, 명찰/회의명패 내용 초안 이름을 사용했다.

독립 SDK 호스트:

- DOCX는 제목 기반 'SDK 0.2.12 DOCX 확인.docx'를 생성했다.
- 공개 inspect의 단순 표 결과가 실제 내보낸 XML과 일치했다.

이는 실제 엔진 검증이며 실제 샌드박스의 신규 업로드/파일 저장 검증은 아니다.
원래부터 보관돼 있던 샌드박스 검증 파일을 탐색했으며 문서 bytes는 변경하지 않았다.

3. 신규 P3: 표시된 기능 이름이 검색되지 않는다

실제 화면에는 '명찰 내용 초안', '회의명패 내용 초안'이 표시된다.
기능 찾기에 '내용 초안'을 입력하면 해당 두 기능이 나오지 않고 현재 선택된
'마크다운 보고서'만 남았다. 검색 조건은 내부 이름의 includes이고 화면의
utilityLabel(name)은 검색 비교에 사용하지 않는다.
관련 위치: packages/react/src/report-automation.tsx:450-457.

현재 선택을 남겨 입력을 보존하는 정책은 적절할 수 있다. 다만 검색 결과가
없는데 관련 없는 선택만 보이면 사용자가 기능이 없거나 검색이 실패했다고
느끼게 된다. 표시 이름을 검색 기준에 포함하고 '검색 결과 없음 / 현재 선택
유지'를 구분한다. 그룹명/기능 별칭 검색도 선택적으로 제공할 수 있다.

수용 기준:
- '명찰', '명패', '내용 초안'이 화면에 표시되는 해당 기능을 찾는다.
- 없는 검색어에는 0개 결과가 안내된다.
- 검색어를 바꾸고 지워도 현재 기능의 원본 입력은 유지된다.

4. 신규 P3: 텍스트 결과를 접어도 큰 빈 열이 남는다

실제 확대 화면에서 구조 작업의 평문 결과는 닫힌 details지만,
.ds-automation-data의 grid-template-columns:1fr 1fr가 유지됐다.
관련 위치: packages/react/src/styles.css:473-475,
packages/react/src/report-automation.tsx:704, 721.

확정한 DOM 크기:
브라우저: 2195×1100 CSS px.
원본/결과 컨테이너: 폭 969.25px, 높이 355px.
원본 입력: 폭 478.625px, 높이 330px.
접힌 결과: 폭 478.625px, 높이 355px, open=false.
구조 미리보기: 시작 y=966.17px, 높이 222.30px.

원본의 옆 공간이 대부분 비었고 구조 미리보기는 스크롤 아래로 밀렸다.
평문 자체를 숨긴 개선은 인정하지만 주요 결과를 앞에 보여주는 목표는 일부만
달성했다. 입력의 빈 열을 회수하거나 구조 미리보기를 그 자리에 놓아야 한다.

개선 선택:
- 구조 작업: 원본/구조 두 열, 평문 결과는 별도의 한 줄 disclosure/탭.
- 단순 계산: 원본/텍스트 결과 두 열 유지.
- 좁은 패널: 원본과 결과의 한 열 배치 또는 전환 탭, 미리보기로 바로 이동.
- 긴 원본: 입력 최대 높이/구조 미리보기까지의 탐색을 조절해 주요 결과를
  보기 위해 입력창 전체를 스크롤할 필요를 줄인다.

수용 기준: 평문 결과를 접었을 때 빈 열이 유지되지 않고, 기본 예제의 표/카드
결과를 사용자가 쉽게 발견할 수 있다. 단순 계산 도구의 결과 입력은 유지한다.

5. 도구 크기와 채팅/문서 대조 — 부분 개선

실제 문서 편집 패널 폭 약 1016px에서 도구 슬라이더를 34→48로 변경했다.
native 문서 높이는 511.5→403px로 줄었다. 도구 크기 조절은 실제로 동작한다.
단계는 2%이며 24~48 범위다. 테스트 후 원래 34로 복원했다.

이 수치는 전체 브라우저의 노트북 크기 수용 시험으로 표시하지 않는다.
viewport 변경 요청을 했지만 실제 샌드박스 DOM은 2195×1100이었다. 의도한
탭의 1366×768 적용을 확인하지 못했고 임시 override는 해제했다.
이번에는 폭이 제한된 실제 편집 패널의 결과를 검증했다. 이전 리뷰의 좁은
전체 화면/모달/채팅 대조 문제까지 새로 통과한 것으로 세지 않는다.

남은 개선은 문서 작업 모드, 문서 스크롤/선택 복귀, 채팅의 변경 항목과
문서 위치 연결이다. 적용 대상 표시가 생긴 것은 좋지만 HWPX의 '문단 번호/
글자 위치'만으로 처음 사용자가 정확한 내용을 알아보기 어렵다. 지원 가능할
때 선택 발췌/표 셀의 내용도 보여주고, 지원하지 않는 범위는 명시한다.

6. 명찰/회의명패 — 정확한 범위 설명으로 개선

현재 '내용 초안' 표시를 실제 메뉴에서 확인했다. 인쇄용 배치를 구현하지 않고
구현한 것처럼 표현하지 않는 것이 맞다. 이전 P2는 표시 문제와 실제 인쇄 업무의
미완료를 구분해 재판정한다. 이름/소속을 문단으로 만드는 기능은 제공하지만
mm 치수·한 쪽 개수·격자·재단선·접힘선은 다음 인쇄 템플릿의 계약이 돼야 한다.

실제 카드 인쇄 결과를 이번에 새로 검증하지 않았다. 0.2.11의 A4 문단 재현을
0.2.12의 신규 실행 결과라고 재사용하지 않는다.

7. 에이전트가 쓰는 화면의 다음 우선순위

SDK 쪽 저장 확정/구조 확인이 생겼으므로 다음은 실제 agent 작업을 연결하는
사용자 흐름이다. 문서와 대상 표시, 변경 항목, 저장 확정, 오류 단계와 재시도를
이어야 한다. 성공한 편집 명령을 서버 저장 완료와 같은 문구로 표시하지 않는다.
이번 commit 해시는 SDK가 제출한 bytes를 뜻하며 서버를 재조회했다는 증명은 아니다.

색상/아이콘을 더 바꾸는 것보다 다음 업무 하나를 완성하는 것이 중요하다.
사용자가 문구 변경과 표 생성을 요청하고, 에이전트가 올바른 대상을 수정하고,
결과 구조/저장 버전/재열기를 확인하고, 사용자가 변경을 검토하는 흐름이다.
실제 연결의 미구현은 agent-sdk-rereview 문서에서 별도로 설명한다.
