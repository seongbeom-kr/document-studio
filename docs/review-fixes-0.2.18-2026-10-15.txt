Document Studio 0.2.18 — DOM 호스트 연결과 HWPX 입력 보존
2026-10-15 / Asia/Seoul

범위
React 앱 밖에서 사용할 수 있는 DOM 진입점과 공통 controller를 추가했다.
별도 편집기 앱/서버를 요구하지 않으며 호스트가 문서 목록·인증·저장소를 소유한다.
UI 영역 배치 API와 실제 General transport는 이 버전의 구현 범위가 아니다.

구현
- @document-studio/core의 EditorController와 createAgentBridge는 React 타입에
  의존하지 않는다. 기존 React export는 동일 계약을 호환 재노출한다.
- @document-studio/browser는 mountDocumentEditor/update/destroy/whenReady를
  제공한다. 호스트는 DOM 요소와 일반 옵션을 전달하며 내부 렌더러는 React다.
  mount는 제어 연결 완료, whenReady는 네이티브 엔진 준비 완료를 의미한다.
- 문서 교체와 종료는 입력 잠금·초안 보관을 기다린다. 실패하면 기존 편집기를
  유지하고 재시도할 수 있다. 호스트의 다른 DOM 자식은 제거하지 않는다.
- 원본 id/fileName/format/version/bytes 변경은 보관 이후 새 세션으로 연다.
  동일 원본의 옵션 변경은 세션을 유지한다. 진행 중인 전환의 중복 명령은 거절한다.
- 엔진·저장소·사용자 namespace 교체는 destroy 성공 후 새 mount로 처리한다.
  readOnly 변경은 네이티브 입력 잠금 반영까지 기다린다.
- 실제 Vue 3 및 일반 JavaScript 소비 예제를 제공한다. 부모 화면이 DOM을 제거하기
  전에 destroy를 기다리는 계약을 명시했다. Vue는 SDK 런타임 의존성이 아니다.

검증 중 발견한 실제 HWPX 결함
고정 RHWP의 짧은 페이지 내부 입력은 document-mutated만 발생할 수 있었다.
기존 document-changed 구독만으로는 revision=0/dirty=false가 남아 즉시 저장의
onlyIfDirty 분기가 입력을 건너뛰었다. 두 네이티브 이벤트를 모두 구독하도록
수정했다. revision은 변경 횟수가 아닌 단조 증가하는 불투명 토큰이다.
짧은 키보드 입력→즉시 저장→종료→저장 bytes 재열기까지 두 브라우저로 검증했다.
