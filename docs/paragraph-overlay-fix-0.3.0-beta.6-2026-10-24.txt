Document Studio 0.3.0-beta.6 — 제목과 로고 겹침 수정

수정 대상
- 공통 SDK UI가 적용됐어도 HWP/HWPX 그림 배치 엔진은 기존 계산을 사용했다.
- 앞선 General 수정은 PDF 미리보기의 임시 사본 보정이었다. 편집기에는 적용되지 않았다.
- RHWP에서 선행 인라인 표가 진행시킨 흐름 y를 문단 기준 글 앞 그림의 기준 y에 덮어썼다.
- SDK의 네이티브 배치 계산을 수정했다. 화면에 그리는 위치와 개체 선택 경계가 같은 좌표를 사용한다.
- 문서의 vertRelTo=PARA, 음수 vertOffset, 그림 크기 및 원본 파일은 수정하지 않는다.

실제 로컬 문서 확인
- 원본 HWP SHA256: 8deed2d1dad090c0fb83cb00dbafcb01211eba59d87bee7f789f70de967fa3eb
- 로고 y: 기존 126.4px → 수정 52.5px. 크기 261.7×36.3px 유지.
- 제목 표: x79.4, y98.2, w631.2, h57.7px 유지.
- 로고가 제목 위에 표시된다. 원본 파일 SHA256은 검증 후에도 동일하다.
- Chrome/Edge × HWP/HWPX 4개 조합에서 실제 화면, 저장, 저장본 재열기와 원래 상대 위치 값 유지 확인.
- 근거: .build/rhwp-native/actual-browser.json 및 actual-*-*.png (고객 문서이므로 Git 제외).

합성 회귀 검사
- 자체 제작 paragraph-overlay.hwpx로 선행 인라인 표 + 문단 기준 글 앞 그림을 재현한다.
- HWP/HWPX, 음수/0/양수 offset, 셀 편집, snapshot 복구, 저장·재열기를 검사한다.
- 글 뒤/어울림/자리 차지 및 인라인 그림은 upstream과 같은 배치인지 비교한다.
- Chrome/Edge × HWP/HWPX 4개 브라우저 검사: 75/100/125% 최종 합성 화면과 그림 선택 테두리 일치 통과.
- SDK 단위 테스트 624개, 타입 검사, 릴리스 WASM 빌드와 WASM Clippy -D warnings 통과.
- 원본/수정 엔진의 전체 render tree 대조: 자체 문서 6개는 동일, 실제 문서는 로고 bbox/y 한 값만 변경.
- 이전 CI의 loadFile-error 시험은 즉시 오류와 무관한 4초 인위 제한을 정상 재연결에도 적용했다. 이 시험만 서비스 기본 30초로 복구를 검증하도록 조정했고 반복 5회 통과했다. SDK의 실제 초기화 제한은 변경하지 않았다.
- 독립 npm 소비 앱 Next.js 빌드, Chrome/Edge × DOCX/HWPX/HWP 6개 및 JS/Vue DOM 12개 조합 통과.
- 기존 브라우저 회귀 및 독립 패키지 소비 앱 검증은 최종 결과를 별도 추가한다.

배포/연결
- SDK 5개 패키지 버전: 0.3.0-beta.6. 공개 npm 배포는 하지 않는다.
- MIT RHWP 0.8.6의 동일 pinned source + paragraph-overlay.patch로 WASM을 빌드했다.
- 대응 JS 바인딩은 npm 0.8.6과 byte-identical. 생성물과 패치의 해시를 빌드·라이선스 검사에서 확인한다.
- third_party/rhwp-core에 소스 패치, 출처, MIT 원문, 도구 버전 및 재빌드 절차를 포함한다.
- SDK만 GitHub에 푸시한다. 프론트 SDK vendor/설치 자산은 로컬 반영하며 원격에 푸시하지 않는다.
- 프론트 scope/로그인 계정은 바꾸지 않는다. 새 편집기를 열어야 새 WASM 인스턴스가 적용된다.

범위/한계
- 독립 SDK의 실제 로컬 문서 렌더링 검증이며 인증된 서비스에서의 모델·서버 저장 왕복 결과를 대신하지 않는다.
- 실제 한컴/Word 프로그램으로 새 저장본을 열어 비교한 검사는 이번 수정에서 수행하지 않았다.
- 글꼴은 기존 자체 호스팅 Noto 대체 정책을 유지한다. 원문 전용 글꼴이 없을 때의 글꼴 차이는 별도 글꼴 팩 확장 과제다.
- 복잡한 그림 묶음·다중 표·모든 HWP 배치의 완전 호환을 보증하는 수정은 아니다.
