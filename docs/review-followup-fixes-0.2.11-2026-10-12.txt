기존 길이 계약 P2는 0.2.10 수정 상태를 유지한다.

수정
1. 문서 저장과 선택적인 자동화 입력 보관 실패를 분리했다.
   save()는 입력 보관 실패에도 문서 저장을 수행하며 onSaved.automationDraft,
   warnings와 getState의 별도 상태를 제공한다.
   flushAutomationDraft()는 문서를 다시 업로드하지 않고 입력 보관만 재시도한다.
   저장 후 닫기·새 문서 생성·lease 이양은 입력 보관/복구 상태를 다시 확인한다.
   flushDraft()는 보존할 수 없는 입력이 있으면 전환을 거절하고 현재 문서를 유지한다.
   초기 조회 실패도 정상 복구 완료로 취급하지 않는다.
2. 원본 template를 사용해 표·명찰·명패·마크다운 구조 미리보기를 추가했다.
   HTML을 해석하지 않고 React 텍스트로 렌더한다.
   미리보기는 80블록·표 20행/12열·텍스트 2000자까지 표시하며 전체 원본과 생성 결과는 유지한다.
   실제 쪽 나눔·크기·서식은 생성한 문서에서 확인한다는 안내를 제공한다.
   원본을 수정하면 이전 미리보기와 생성 template를 폐기한다.
3. 문서 저장 완료와 입력의 로컬 보관/메모리 유지/보관 실패 문구를 구분했다.
4. 실제 프론트에서 HWPX 초기 배율 문제를 추가 발견했다.
   RHWP CanvasView.loadDocument는 iframe 폭이 1024px 미만이면 모바일 맞춤을 적용한다.
   데스크톱의 좁은 파일 패널도 이 조건에 들어가 121%로 열렸다.
   SDK 어댑터가 문서 로딩 후 배율을 한 번 100%로 초기화한다.
   이후 사용자 배율은 재렌더링·패널 폭 변경으로 초기화하지 않는다.

호스트 반영
기존 작업 트리는 보존하고 최신 dev에서 새 격리 브랜치를 만들었다.
문서 저장 성공 후 자동화 입력이 남으면 닫기·새 문서 업로드·편집권 이양을 차단한다.
문서 자체의 저장 성공은 유지하며 별도 입력 보관 경고를 표시한다.
네 SDK tarball·체크섬·버전 표시를 0.2.11로 갱신했다.
Next.js 소비 예제도 입력 보관소를 명시적으로 연결하고 전환 전에 flushDraft를 기다린다.
메모리 입력 전환 보호를 시험하는 별도 케이스를 유지했다.
