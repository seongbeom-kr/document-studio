# 오픈소스 개선 후보와 범정부 오피스 기능 점검

2026-10-06 KST, Document Studio 0.2.2와 현재 샌드박스 연결 코드를 기준으로 조사했다. **기본 문서 편집과 업무 보조 함수는 있지만, 범정부 오피스의 주요 작업 흐름까지 모두 완성된 상태는 아니다.** 가장 먼저 채울 부분은 실제 선택한 표에 적용하는 자동화, 새 보고서 생성의 호스트 연결, 글상자·캡션·인쇄 서식이다. 엔진 측에서는 DOCX 2.26.0 평가와 RHWP의 편집 후 서식·표·저장 보존 관련 수정을 우선 검토할 가치가 있다.

리뷰 중인 제품 소스·의존성·실행 서버는 변경하지 않았다. 이번 결과는 공개 자료·GitHub API·npm 메타데이터·로컬 코드와 기존 검증 산출물을 대조한 조사다. 후보 버전을 설치하거나 후보 PR의 버그를 현재 SDK에서 새로 재현한 결과는 아니다.

## 조사 기준

범정부 오피스는 [행정안전부의 2026-08-04 공개 게시물](https://sotong.go.kr/front/board/boardContentsView.do?board_id=240&contents_id=7bf5da6228d146fcade014ede52bb129&menu_id=606)의 KISA 1310일판을 공개 비교 기준으로 삼았다. 첨부 가이드북은 1100일판이므로 실행판과 가이드북의 범위가 다를 수 있다. 공식 다운로드의 PDF bytes가 기존에 읽은 91쪽 가이드와 동일함도 확인했다. 기관 내부망의 최신 실행판이나 1,000여 개 전체 명령을 확인한 것은 아니다.

RHWP와 EigenPal은 열린 PR 전체와 최근 갱신된 닫힌 PR 각 50개, 관련 이슈·릴리스를 확인했다. PPTX·XLSX는 후속 형식에 관련된 최근 PR·릴리스를 확인했다. PR 목록 페이지에는 캐시된 과거 상태가 남아 있어, 상태 판정은 조사 시점의 GitHub API `state`와 `merged_at`을 사용했다. 닫혔다는 이유만으로 병합됐다고 판정하지 않았다.

기능 상태는 공통 SDK 명령, 형식별 고급 메뉴, 원본 파일 보존, 실제 호스트 연결, 시험 근거를 구분했다. 상류 프로젝트의 테스트 통과 설명은 우리 SDK의 테스트 결과로 계산하지 않았다.

## 로컬 코드에서 확인한 연결 공백

### 새 문서 생성

[report-automation.tsx](../packages/react/src/report-automation.tsx)의 ‘새 문서로 만들기’는 `createDocument`와 `onCreateDocument`가 모두 있어야 활성화된다. 실제 프론트 `DocumentStudioPanel`의 `DocumentEditor`에는 `onCreateDocument`가 전달되지 않는다. 따라서 standalone fixture에서 통과한 마크다운·참석자 문서 생성이 현재 샌드박스에서도 완료됐다고 볼 수 없다.

텍스트 결과 삽입은 남아 있지만 제목·표·목록 구조를 가진 factory 결과 전체를 적용하는 것과 다르다. 명패·명찰 factory도 현재는 이름/소속 문단 생성이며 인쇄 배치 생성기가 아니다. 수정 방향은 SDK가 문서 bytes 생성 이벤트를 제공하고, 호스트가 신규 파일 이름·저장소·lease·파일 목록 갱신을 맡는 것이다.

### 선택 범위 자동화

[office-automation.ts](../packages/core/src/office-automation.ts)의 `transformCells`, `reverseTotals`, `consolidateRows`, `sortByOrganization`은 입력 데이터를 반환하는 함수다. [UI](../packages/react/src/report-automation.tsx)는 사용자가 넣은 텍스트를 계산하고 `insertText`로 결과를 삽입한다. 기존 표 셀을 문서 ID·revision·셀 주소로 읽고 미리보기 후 부분 수정하는 API가 필요하다. 병합 셀·중첩 표·그림/필드를 읽거나 수정할 수 없으면 명시적으로 거절해야 한다.

### 에이전트 연결

[agent-bridge.ts](../packages/react/src/agent-bridge.ts)에는 명령 조회·문서 읽기·검색·선택·치환·preset·execute와 대상/revision 검증이 있다. 하지만 20개 업무 보조 기능을 공통 schema로 조회·실행하는 workflow API는 없다. 실제 `DocumentStudioPanel`도 `createAgentBridge`를 등록하지 않는다. 이 판단은 live 편집기 SDK 연결에 대한 것이며, 기존 General Agent가 별도로 파일을 만드는 능력이 없다는 뜻은 아니다.

### 고급 객체와 날짜 기본값

현재 DOCX 어댑터는 frame 범위 자동 치환을 거절한다. 엔진 글상자 지원이 늘어도 SDK에 안전한 story 범위 연결이 필요하다. 공통 캡션·머리말·꼬리말·쪽 번호·누름틀 명령도 없다. UI의 자동화 추가 인수 기본값은 `2026-10-05`로 고정돼 있어, 날짜·나이 기능에는 명시적인 기준일 필드와 실제 오늘 날짜 기본값을 검토해야 한다.

## 후속 오픈소스 후보와 라이선스 경계

PDF 읽기는 [PDF.js](https://mozilla.github.io/pdf.js/)가 Apache-2.0 후보다. 텍스트 추출과 스캔 문서 OCR은 다른 기능이다. Worker 취소·페이지/메모리 제한·여러 열과 줄바꿈·한글·쪽 출처가 평가 항목이다. 고정 최신 버전을 바로 추가하지는 않았다.

실제 XLSX 취합에는 MIT [office-kit/xlsx](https://github.com/office-kit/xlsx)를 비교할 가치가 있다. 프로젝트는 pre-1.0 alpha다. [#253](https://github.com/office-kit/xlsx/pull/253)의 열 이름·구조화 수식 보존, [#251](https://github.com/office-kit/xlsx/pull/251)의 차트 계열/축, [#257](https://github.com/office-kit/xlsx/pull/257)의 필터 조건 보존을 추적한다. 모두 조사 시점에 열린 PR이므로 최신 0.23.4에 해결됐다고 표시하지 않는다. 셀 데이터를 추출해 새 취합 파일을 만드는 기능과 기존 workbook 전체를 충실히 편집하는 기능은 별도로 검증한다.

PPTX에는 Apache-2.0 [pptx-viewer](https://github.com/ChristopherVR/pptx-viewer)를 유지 후보로 둔다. [#404](https://github.com/ChristopherVR/pptx-viewer/pull/404)는 가로/세로 선 누락 수정으로 병합됐다. #390/#400의 공유 UI·상태/의도 구조도 임베드 계약 참고가 된다. 최신 버전 적용 전에 기존 테마 글꼴 패치·표·그림·도형·저장 회귀를 비교해야 한다.

EigenPal의 무료 core/react는 Apache-2.0이지만 [editor-api](https://www.docx-editor.dev/docs/2.x/editor-api), [DOCX→PDF 변환 패키지](https://www.docx-editor.dev/docs/2.x/export/pdf), Pro의 변경 추적·댓글·협업은 상용 조건이다. 현재 MIT/Apache 공개 목표에 이 패키지들을 무료 의존성으로 넣을 수는 없다. GitHub 저장소에서 보인다는 이유로 모든 하위 패키지를 같은 라이선스로 판단하지 않는다. 우리 agent 명령 계약은 무료 엔진 API 위에 유지한다.

## 평가에 추가할 시험

- 실제 키 단위 타이핑과 Windows 한글 IME: 빈 문단·셀·그림 전후, 조합 중 서식·undo·재열기.
- 여러 쪽 단일 셀, 병합 시작 행 삭제, 중첩 표, 긴 URL과 AutoFit. DOM 표시 외에 구조 XML과 독립 프로그램의 결과를 확인한다.
- HWPX 들여쓰기·내어쓰기 문단 편집, 새 문서 fallback XML, 첫 구역 문단·표 뒤 문단의 저장 왕복.
- 셀 병합 전후 문단·필드·빈 줄·그림 수와 내용, 필드 주변 삽입·삭제, 따옴표·역슬래시 보존.
- 선택 셀 대상이 미리보기 후 바뀌는 경우, 실패한 다중 적용·undo·권한 변경·저장 충돌에서 부분 수정 방지.
- 새 보고서/명패/명찰 생성의 실제 host 저장, 파일 목록 갱신, 다른 사용자 namespace·lease와 늦은 응답.
- XLSX 복수 파일·다른 시트/열·병합 셀·날짜·수식·차트·필터와 한 파일 실패. 단순 값 취합과 원본 보존의 기대 결과를 분리한다.
- PDF의 한글·다단·표·스캔 이미지·암호화·큰 파일·취소, 추출할 텍스트가 없는 경우의 명시적 오류.
- 정상 고압축 문서와 악성 ZIP·XML·손상 이미지·Worker 중단을 함께 검사해 호환성 때문에 보호 제한이 사라지지 않도록 한다.

기존 218개 단위 시험, 336개 전체 E2E와 4개 추가 UI 시험, 프론트 537개 시험의 통과는 [0.2.2 검증 기록](review-fixes-0.2.2-2026-10-05.md)의 범위다. 이번에 후보 엔진·새 기능 시험을 실행한 수치가 아니다. 실제 샌드박스 브라우저 접근 차단과 미완료된 문서 편집 통합 시험도 기존 기록대로 남아 있다.
