수정 1: 검색 조건/결과/선택 연결
검색 결과는 문서 ID/편집 세션/revision/검색어/대소문자/단어 단위 조건과 함께 보관한다.
조건을 바꾸면 결과와 선택을 즉시 무효화한다. 늦은 검색/선택 응답과 오류는 버린다.
반복 검색 및 연속 선택에는 요청 세대를 사용한다. 선택 치환은 현재 결과 안에 있는
선택과 현재 revision이 일치할 때만 활성화한다. 검색/선택 처리 중 상태를 표시한다.
문서 재열기·전환·unmount 이후 오래된 선택을 다시 쓰지 않는다. 읽기 전용에서는 치환을 비활성화한다.

수정 2: 실행 중 preset의 권한/세션 검사
각 후속 명령 전후에 읽기 전용, 세션, 원본, namespace와 지원/활성 상태를 검사한다.
읽기 전용으로 한 번 전환되면 곧 권한이 복구되어도 해당 preset은 중단한다.
요청 명령도 미리 복사하므로 실행 중 호출자가 배열을 바꿔 후속 명령을 교체할 수 없다.
PresetApplicationError.completedCommands/totalCommands로 중단 지점을 반환한다.
이미 엔진 응답으로 확인된 단계는 현재 편집본에 남고, 아직 전송하지 않은 명령은 실행하지 않는다.

수정 3: 강조색 제약 전달
DOCX 엔진은 CommandState.valueChoices와 valueSchema.enum으로 Word의 16색을 제공한다.
SDK UI는 그 팔레트를 사용하고, 에이전트 listCommands에도 같은 schema를 노출한다.
글자색과 강조색 입력은 분리한다. DOCX 글자색 및 HWPX 강조색은 자유 RGB 입력을 유지한다.
허용되지 않은 팔레트 값은 적용 버튼을 활성화하지 않는다.

남은 범위
순차 preset은 단계별 native Undo를 사용한다. 한 번의 preset/한 번의 Undo 및 전체
롤백은 별도의 엔진 transaction 기능 개선으로 남는다. 수치 표시 정돈, 자동화 입력
필드 개편, 그림 비율/위치 안내도 이번 신규 P2 세 건의 수정 범위와 구분한다.
실제 Word/한컴/물리 Windows IME와 실무 corpus는 이번 시험의 합격 범위가 아니다.
인증된 sblim 브라우저 접근은 저장된 사용자 설정으로 차단돼 화면 조작/운영 lease
통합을 우회하지 않는다. 로컬 health는 인증된 파일 저장 시험의 증거가 아니다.
Apache-2.0과 고정 의존성을 유지했으며 새 production 의존성을 추가하지 않았다.
push/merge/npm publish는 수행하지 않았다.
