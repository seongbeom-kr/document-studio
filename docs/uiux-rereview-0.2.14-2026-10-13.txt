1. 사용자 경험 판정

차트 도움말과 버튼의 불일치는 해결됐다. 그림·텍스트·새 문서 생성이
결과 형식별로 구분돼 사용자가 가능한 다음 행동을 이해하기 쉬워졌다.
실제 차트 삽입과 문서 템플릿 생성도 두 형식의 독립 엔진에서 확인했다.

이번 범위에서 새 P1/P2 문제는 발견하지 못했다. 다만 사람의 기본 사용
동선에는 개선할 부분이 남는다. 실제 1366×900 화면에서 확장하지 않은
도구 본문은 42px였고 폼이 거의 보이지 않았다. 작업 가능 여부와 첫 화면의
이해·발견·편의는 별개이므로 이 사용성 문제를 P3로 남긴다.

실제 사용자 대상 연구나 전체 업무 완료 시험을 수행한 것은 아니다.
화면·DOM·합성 문서 검증을 근거로 한 전문가 리뷰이며, 전체 제품이
사람과 에이전트에게 충분히 편하다는 포괄 판정을 내리지 않는다.

2. 수정된 안내를 실제 화면에서 확인

실제 sdk-live-B.hwpx의 편집기를 열었고 버전 속성 0.2.14를 확인했다.
업무 자동화에서 차트를 선택해 기본 데이터로 미리보기를 만들었다.
그림 1개가 표시됐고 '그림을 선택 위치에 삽입' 및 평문 삽입이 안내됐다.
새 문서 생성 버튼은 없었다. 이전 P3의 오해를 만드는 안내가 사라졌다.

'도구 크게 보기' 상태에서는 차트 원본과 그림이 좌우로 보였다.
원본 입력 수정과 삽입의 역할을 구분할 수 있었다. 미리보기는 문서에
자동 적용되지 않으며 실제 삽입 행동을 따로 선택하는 흐름이 유지됐다.
실제 서버 문서에는 삽입하지 않았다. 삽입 동작은 독립 합성 문서에서 검사했다.

3. 독립 호스트의 결과별 다음 행동

DOCX 계산 결과: 결과를 '0.2.14 계산 결과 보정'으로 직접 수정할 수 있었다.
이 기능에 새 문서 버튼은 없었다. 계산 결과를 문서 맥락에 맞게 조정하고
텍스트로 삽입하는 범위와 안내가 맞았다.

DOCX/HWPX 그림 결과: 조직도 그림과 차트에서 미리보기 그림 각 1개를
확인했다. 호스트에 생성 기능이 없어도 그림 삽입 버튼은 활성 상태였다.
두 형식 모두 차트를 실제로 삽입하고 내보낸 XML에서 그림 객체를 확인했다.

DOCX/HWPX 문서 결과: Markdown의 2×2 표 미리보기 후 생성 지원을 끄면
생성 버튼이 비활성이고 '이 앱에서는 새 문서 생성을 지원하지 않습니다.'가
표시됐다. 지원을 켜면 입력을 보존한 채 버튼이 활성화됐고 실제 새 문서가
생성됐다. 해당 파일의 기본 표와 텍스트는 공개 inspect로 확인했다.

4. P3: 기본 도구 본문이 작은 스크롤 창으로 남는다

환경: 실제 샌드박스, 1366×900 CSS px, sdk-live-B.hwpx, 배율 100%,
도구 영역 크기 34, 업무 자동화, data-expanded=false.
도구 전체 높이 195.5px, 본문 높이 42px, 헤더 높이 51px였다.
본문의 위치는 x=336, y=760, 폭=1023px였다.
첨부 화면에는 탭 아래 안내만 조금 보이고 자동화 입력이 화면 아래에 남는다.

영향: 기능을 고르고 입력하려는 사용자가 내부 스크롤 또는 확장 버튼을
먼저 발견해야 한다. 도움말·적용 대상·크기 조절·탭을 지나 실제 작업까지
도달하는 비용이 커진다. 화면의 큰 빈 문서 영역과 좁은 폼이 동시에 보여
실제 작업 공간의 우선순위가 사용자의 목적과 맞지 않는다.

완화: '도구 크게 보기'를 누르면 전체 높이 575px, 본문 448.5px였다.
이 모드에서 입력과 결과를 다룰 수 있어 기능 차단이나 데이터 손실은 아니다.
도구를 확장한 동안 문서를 직접 대조하려면 다시 '문서와 함께 보기'로
돌아가야 하므로 확장 버튼의 존재만으로 기본 배치 문제가 없어지지는 않는다.

원인 위치: packages/react/src/styles.css:360–362의 세로 배치와 비율 높이.
기본 34는 packages/react/src/editing-tools.tsx:67–70에 있다.
이번 안내 수정의 새 회귀가 아닌 현재 남은 기본 배치 문제다.

권장: 헤더를 제외한 폼 본문의 최소 가용 높이를 기준으로 배치한다.
실제 공간이 부족하면 업무 자동화 탭은 확장 상태로 열거나 문서/도구 전환을
명시적으로 제공한다. 반복 안내와 조절 영역은 접을 수 있게 하고 주요
입력·미리보기 행동은 첫 화면에서 발견할 수 있게 한다.
완료 기준: 같은 노트북 크기와 기본 상태에서 기능 선택·원본 입력·미리보기
행동을 사용자가 좁은 내부 영역을 먼저 스크롤하지 않고 찾을 수 있다.

5. 추가 개선 권고

생성 지원이 없는 호스트에서는 새 문서 파일명·저장 위치 영역도 검토한다.
현재는 생성 버튼이 비활성이고 이유는 설명하지만 파일명 입력은 남는다.
삽입만 지원하는 임베딩 앱에는 필요 없는 입력을 숨기거나 지원 범위를 먼저
보여주면 동선이 더 명확해진다. 낮은 우선순위의 개선 권고로 분류한다.

채팅 변경 항목과 실제 문서 위치를 연결한다. 사용자가 적용 대상·변경 전후·
저장 확정을 쉽게 대조할 수 있어야 한다. 실제 General 호출 결과를 파일과
함께 보여주는 흐름은 아직 확인되지 않았다. 도구 도움말만 다듬어서는
사람이 에이전트 업무 완료를 판단하는 경험까지 완성되지 않는다.

명찰/회의명패는 현재 내용 초안 범위를 유지한다. 인쇄 기능으로 확장할
때는 용지·mm 치수·한 쪽 배치·재단선·접힘선과 실제 파일 결과를 별도로
검증한다. 텍스트 내용 생성 성공을 실제 인쇄 업무 성공으로 표시하지 않는다.

6. 범위와 종료 상태

이번 실제 반응형 확인은 1366×900이며 480px 전체나 모바일 전체 시험이 아니다.
실제 원래 Markdown 92자를 유지했고 sdk-live-B.hwpx의 표시 hash/revision 7은
검사 전후 같았다. 실제 bytes·채팅·서버 파일은 변경하지 않았다.
종료 시 편집을 끝내고 파일 목록으로 복귀했으며 viewport를 원래 상태로 돌렸다.
독립 호스트는 합성 문서와 메모리 storage를 사용했다. 탭과 임시 서버를 종료했다.
제품 소스·커밋·푸시는 변경하지 않았다. 물리 IME·전체 접근성·인쇄는 미검증이다.
