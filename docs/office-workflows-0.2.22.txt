Document Studio 0.2.22 — 빠른 작업·표 열 가공·사용자 서식 메일머지

설계
사용자 제공 범피스 기능 보고서를 참고해 웹에서 재사용 가능한 기능을 자체 구현했다.
범피스 실행 파일·소스·이미지·기관 양식을 복사하지 않았고 새 런타임 의존성도 추가하지 않았다.
UI와 React/DOM controller, agent bridge가 같은 미리보기와 실행 계층을 사용한다.
UI의 빠른 작업 및 서식·메일머지 탭은 기존 ui.containers, theme, slots 구성에 포함된다.

1. 빠른 작업
listQuickActions()는 현재 브라우저의 시간대·기준일, 날짜 작업, 보고서/호스트 preset,
입력 스키마를 반환한다. 날짜는 baseDate를 YYYY-MM-DD로 명시한다.
today/yesterday/tomorrow, thisWeek/nextWeek, thisMonth/nextMonth, thisYear/nextYear를 제공한다.
week=workweek는 월~금, calendar는 월~일이다. 공휴일 제외 계산은 아니다.
format=official(요일 포함), iso, compact를 지원한다. 달력 계산은 명시한 기준일로 고정된다.
서식은 기존 REPORT_PRESETS와 호스트 presets를 이용하며 서식 전용 명령만 허용한다.

const p = agent.previewQuickAction({
  documentId: agent.getState().documentId,
  action: { kind: 'date', baseDate: '2026-12-31', period: 'nextWeek',
    week: 'workweek', format: 'iso' },
});
// p.target, p.text 또는 p.commands를 표시하고 사용자가 확인한 뒤 실행한다.
const receipt = await agent.applyQuickAction({
  documentId: p.documentId, expectedSessionId: p.sessionId,
  expectedRevision: p.revision, expectedSelectionKey: p.selectionKey,
  previewId: p.previewId, operationId: crypto.randomUUID(),
});

대상은 현재 선택/커서이며 documentId·sessionId·revision·selectionKey를 확인한다.
권한과 실행 가능 명령도 적용 직전에 다시 확인한다. preview는 내부 복사본으로 실행한다.
동일 operationId/previewId의 재요청은 결과/실패를 재전달하며 다시 편집하지 않는다.
실패한 preview는 새 ID로도 재실행할 수 없다. 새 상태를 읽고 다시 미리보기한다.
QuickActionError.effect=unknown이면 부분/완료 여부를 확인하기 전 자동 재시도하지 않는다.
receipt.committed=false는 파일 저장 전이라는 뜻이다. 변경은 한 번 Undo로 복구한다.
revision이 바뀌지 않은 실행은 undoSteps=0을 반환한다.
HWPX의 선택 삭제+텍스트 삽입도 하나의 native history 작업으로 묶었다.
새 SDK와 함께 HWPX 런타임 자산을 다시 복사해야 한다. 원자적 삽입 기능이 없으면 거절한다.

2. 표 열 가공
기존 readTable → previewTableColumn → applyTableColumn에 아래 operation을 추가했다.
{ kind: 'prefix', text: '앞말 ' }, { kind: 'suffix', text: ' 뒷말' },
{ kind: 'trim' }, { kind: 'collapseSpaces' }.
collapseSpaces는 일반/비분리/전각 공백을 한 칸으로 정리하고 앞뒤 공백을 제거한다.
접두/접미사 입력은 1~1,000자이며 제어 문자는 거절한다.
열 번호·자료 종류·제목 행·대상 셀과 전후 값/제외 이유를 확인한 뒤 일괄 적용한다.
기존 사번/날짜 보호, 복잡한 셀 제외, revision/선택/권한 가드, 일괄 Undo를 유지한다.
자세한 기존 계약: table-column-editing-0.2.21.txt.

3. 사용자 서식과 메일머지
서식의 일반 텍스트에 {{이름}}, {{소속}} 같은 필드를 넣고 현재 문서를 등록하거나
DOCX/HWPX 파일을 선택한다. 필드 목록과 본문/표/지원 영역의 위치를 표시한다.
CSV/TSV 첫 행은 고유한 열 이름이다. mapping은 서식 필드 → 데이터 열 이름이다.
값은 모두 문자열로 취급해 사번 앞자리 0, 날짜, 큰 정수 등을 변환하지 않는다.
모든 출력 파일명·필드 값·빈 값·문제를 미리보기하고, 문제를 해소해야 생성한다.
빈 값은 allowEmpty=true로만 허용한다. 누락된 데이터 열은 허용하지 않는다.
파일명은 {{필드}}, {{#}}(두 자리 순번)를 지원한다. 경로/예약 이름/대소문자 중복은 거절한다.

const template = await agent.registerCurrentMailMergeTemplate({
  documentId: agent.getState().documentId,
});
const p = agent.previewMailMerge({
  documentId: agent.getState().documentId,
  mergeRequest: { templateId: template.templateId,
    data: '이름,소속\n홍길동,기획팀', delimiter: ',',
    mapping: { 이름: '이름', 소속: '소속' },
    fileNamePattern: '안내문-{{이름}}-{{#}}.docx', allowEmpty: false },
});
// p.files, p.emptyValues, p.issues를 모두 확인한다. 확장자는 서식 형식과 같아야 한다.
const receipt = await agent.generateMailMerge({
  documentId: p.documentId, expectedSessionId: p.sessionId,
  expectedRevision: p.revision, previewId: p.previewId,
  operationId: crypto.randomUUID(),
});
// 호스트에서만 binary를 받는다. 저장/업로드 성공 뒤에만 호스트 목록을 갱신한다.
const files = editor.exportMailMerge(receipt.operationId);

listMailMergeActions는 스키마/워크플로를, getMailMergeStatus는 진행 상태를 제공한다.
cancelMailMerge({documentId, operationId})는 취소를 요청한다. 완료 상태를 다시 확인한다.
General 연결은 세션 가드를 추가하며 operationId를 서버에서 부여한다.
생성 중 권한 또는 현재 문서/session/revision이 바뀌면 해당 배치의 출력 전체를 폐기한다.
이전 성공 배치는 새 배치가 모두 성공할 때까지 보관한다. 실패/취소한 부분 출력은 공개하지 않는다.
0.2.23부터 이전 배치의 보관 확인 또는 명시적 폐기 전에는 새 배치를 거절한다.
보관 확인 후 새 성공 배치가 생기면 이전 배치의 bytes는 해제한다. 재요청 receipt 자체는 유지된다.
파일별 보관 영수증과 종료 가드는 generated-output-lifecycle-0.2.23.txt를 참고한다.
UI는 ZIP 다운로드를 제공한다. 생성/다운로드 요청/서버 저장은 서로 다른 상태다.
agent 결과에는 파일명·digest·byteLength만 전달한다. 기본 transport는 bytes를 보내지 않는다.
읽기 전용에서는 미리보기는 가능하지만 생성은 허용하지 않는다.

보존 및 제한
- 서식 2개, 배치 20행, 필드 100개, 위치 1,000개, 입력 100,000자, 셀 값 2,000자.
- 서식 압축 8 MiB, 전체 해제 32 MiB/단일 항목 8 MiB, 출력 합계 64 MiB.
- 실제 해제량을 검사하는 기존 validation Worker를 먼저 통과해야 한다.
- 문단 내 여러 글자 run에 나뉜 필드도 지원한다. 필드 첫 run의 서식을 적용한다.
- 본문/표 일반 문단, DOCX 머리말/꼬리말 텍스트를 지원한다.
- 텍스트 필드와 이미지/필드 코드/추적 변경 등 복잡한 객체가 섞인 문단은 거절할 수 있다.
- DOCX 주석/각주/미주 필드와 전자서명 문서는 거절한다. 이미지 치환·행 반복·조건부 필드는 없다.
- 입력에 {{다른필드}}가 있어도 다시 치환하지 않는다. XML 특수 문자도 텍스트로 보존한다.
- 수정하지 않은 media/styles와 다른 ZIP 항목은 그대로 보존한다.
- 변경된 HWPX 문단의 오래된 linesegarray는 삭제해 다시 조판하게 한다.
  공식 근거: https://forum.developer.hancom.com/t/hwpx-section0-xml/2414/2
- HWPX PrvText를 갱신하고 기존 문서 썸네일은 일반 생성 문서 이미지로 바꾼다.
  이 이미지는 실제 페이지 렌더 미리보기가 아니다. 외부 앱에서 실제 조판을 재확인해야 한다.
- 입력/필드 연결은 호스트의 사용자·세션별 automationDraft 정책을 따른다.
  서식 bytes·출력 bytes는 편집 세션 메모리이며 재열기 시 서식 재등록이 필요하다.
  손상된 필드 설정은 다운로드/명시적 초기화 전까지 덮어쓰지 않는다.
- 모든 업무 문서/한컴 설치본 호환성을 보장하지 않는다. 현재 브라우저 엔진으로 생성·재열기를 시험했다.

이 기능은 독립 앱이나 LLM 서비스가 아니다. 문서 목록·인증·권한·서버 저장·모델 연결과
자동화 초안 namespace 정책은 호스트가 담당한다. 새 문서의 서버 업로드도 명시적으로 연결한다.
