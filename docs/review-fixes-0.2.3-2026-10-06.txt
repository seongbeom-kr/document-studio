수정 경계
SDK에서 초안 저장소 승인, 조회 실패 처리, 편집 세션 식별, 원자적 DOCX 치환을 수정한다.
프론트에서 이전 버전 사전 검증, 초안 교체, 파일 목록 복귀, 페이지 이탈 경고를 수정한다.

P1 초안 보존
1. DraftStore 변경 시 새로운 키를 먼저 조회한다. 빈 저장소는 엔진 재마운트 없이
   승인한다. 복구 자료가 있으면 현재 편집본을 유지하고 명시적 전환을 요구한다.
   조회/동의 전에는 새 저장소에 쓰거나 삭제하지 않는다. 전환 시 현재 입력은
   기존의 승인된 저장소에 보관한 뒤 새 저장소의 복구/원본 선택을 제공한다.
2. 초안 get 실패는 빈 키로 간주하지 않는다. 초기 문서는 편집 가능하게 마운트하지
   않으며 오류와 재시도를 제공한다. 교체 중 실패하면 기존 편집본을 유지한다.
3. 샌드박스 DOCX/HWPX 이전 버전은 SDK 엔진 validator의 Worker에서 크기/압축/파싱 검사를
   먼저 수행한다. 검증 동안 입력과 기존 자동 쓰기를 중지한다. 실패하면 기존
   편집기/초안 키를 유지한다. 성공한 IndexedDB put 이후에만 편집기를 교체한다.
   검증 중 종료/편집권 변경도 보관된 현재 초안을 교체하지 않는다.

P2 명령과 UI
4. 에이전트 쓰기에는 documentId, expectedSessionId, expectedRevision이 필요하다.
   getState/search의 sessionId를 사용한다. 동일 ID/원본 버전/revision으로 다시
   열어도 sessionId를 갱신한다. 비동기 완료 시 세션/버전도 다시 검사한다.
   expectedVersion을 주면 서버 저장 버전도 확인한다. 이전 API 소비자는 갱신 필요.
5. DOCX 본문/표의 모두 바꾸기는 EigenPal 공개 BrowserAutomationHost의 원자적
   batch로 실행한다. Undo/Redo 한 번으로 전체가 복구되며 후속 편집은 별도 단계다.
   HWPX의 native 전체 치환도 한 단계이다. 본문 외 DOCX 전체 치환은 명시적으로
   거부하고 개별 치환을 사용한다. 여러 명령의 preset은 여전히 순차 Undo이다.
6. 문서 열기 시 선택한 inline/sheet 편집기를 화면 크기가 바뀌어도 유지한다.
   파일 목록 복귀는 files 탭을 선택하고 좁은 화면의 Sheet도 명시적으로 연다.
7. 깨끗한 문서는 beforeunload를 막지 않는다. 미저장 변경/복원 작업/미확인 서버
   저장은 경고한다. lease는 기존 pagehide/unmount 경로에서 해제한다.

네 패키지는 0.2.3, Apache-2.0. EigenPal 2.25.0/RHWP 0.8.6 고정 유지.
외부 엔진 패치나 상용 모듈, 새 production 의존성을 추가하지 않았다.

한글 문자열/중복을 검사한다. 손상된 버전 복원 이후 다른 버전 재선택도 검증했다.
