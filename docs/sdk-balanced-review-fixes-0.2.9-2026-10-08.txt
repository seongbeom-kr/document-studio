변경

1. 새 문서 생성과 편집 lease 충돌 — 프론트 연결 수정
DocumentEditingSession.withHandoff가 현재 문서 입력 잠금, 최종 저장,
진행 중 lease 갱신 대기, lease 해제를 완료한 뒤 업로드를 실행한다.
호스트의 기존 세션 전체 잠금 정책은 수정하지 않았다.
생성 또는 열기 실패 시 이전 문서의 lease를 재확보한 뒤 입력 잠금을 푼다.
재확보 실패 시 입력을 잠근 채 명시적 오류와 재시도를 제공한다.
업로드 완료와 목록 갱신/새 문서 열기를 구분하는 기존 중복 방지 정책을 유지한다.

2. 닫기 확인창 public 쓰기 우회 — SDK 수정
execute, replace, applyPreset이 공유하는 신규 쓰기 판단에 확인창 상태를 추가했다.
확인창 표시 즉시 ref를 잠그며 native 입력과 명령 지원 상태에도 반영한다.
계속 편집/취소 후 다시 명령을 사용할 수 있다.
이전에 승인되어 실행 중인 작업은 저장/전환에서 끝까지 기다린다.

3. 구조 있는 자동화 미리보기 — SDK 수정
보고서/명단/명패/명찰/조직 자료/그림 결과는 읽기 전용이며 생성 기준을 표시한다.
'원본 입력 수정'이 실제 입력란에 포커스를 옮긴다.
원본 변경 시 미리보기를 무효화하고 다시 생성한 결과로 문서를 만든다.
평문 결과의 직접 편집 기능은 유지한다. 예제 초기화 전 입력의 복구도 제공한다.

4. 자동화 입력 보관 — SDK와 프론트 연결 수정
문서 bytes와 별도인 AutomationDraftStore와 browserAutomationDraftStore를 추가했다.
호스트가 명시적으로 opt-in한다. 샌드박스는 사용자/작업/문서 namespace로 연결했다.
기능별 원본 입력, 추가 인수, 셀 변환과 열 구분을 IndexedDB에 보관한다.
조회/쓰기 실패는 표시하고 재시도를 제공하며 손상된 입력은 자동 덮어쓰지 않는다.
save/flushDraft는 입력 보관을 기다린다. 호스트는 닫기 전 두 API 중 하나를 기다려야 한다.
기본 메모리 모드에는 닫기 경고와 입력 JSON 다운로드를 제공한다.
열린 세션에서 저장소 객체/namespace를 임의 변경하지 않는 호스트 계약을 README에 기록했다.
로컬 브라우저 보관이며 서버 동기화나 다른 기기 복구 기능은 아니다.

5. 키보드 도구 탭 — SDK 수정
선택 탭만 tabindex=0, 방향키 순환과 Home/End 이동, 자동 선택/포커스를 제공한다.
aria-controls, tabpanel, aria-labelledby로 관계를 연결한다.
Escape로 도구를 닫으면 열기 버튼으로 포커스를 돌린다.

6. 좁은 화면 — SDK 수정
'도구 크게 보기'로 편집 작업 영역 전체에 긴 입력 공간을 제공한다.
문서 엔진을 제거하지 않고 입력을 잠가 편집본을 유지한다.
Escape로 함께 보기로 돌아오며 입력값을 유지한다.

추가로 발견한 문제

HWPX 생성기는 insertParagraph가 지정 index 앞에 삽입한다는 native 계약을 잘못 사용했다.
제목과 본문이 합쳐지고 앞에 빈 문단이 생기는 문제를 다음 index 삽입으로 수정했다.
실제 WASM 생성/재열기에서 제목, 본문, 표, 후속 문단 순서와 한 페이지 배치를 검사한다.

입력 보관을 기다리는 동안 이전 명령이 실패하면 대기 집합에서 먼저 제거될 수 있었다.
저장/초안 전환 시작 시 승인된 작업들의 Promise를 고정해 실패도 반드시 전달하도록 했다.
기존 프론트의 느린 명령 실패 검사를 유지하고 SDK 브라우저 회귀 검사도 추가했다.

초기 실패와 처리

공통 쓰기 차단의 오류 문구 변경 때문에 기존 저장 중 보호 검사 2건이 실패했다.
기존 '저장 중' 안내를 유지했고 최종 전체 검사에서 다시 통과했다.
프론트의 실제 SDK 사용 경계 검사에는 jsdom IndexedDB가 없어 저장소 대역을 연결했다.
실제 IndexedDB 보관·닫기·새로고침·다른 owner 분리는 두 브라우저 SDK 검사에서 수행했다.
그 과정에서 발견한 이전 명령 실패 누락은 제품 코드에서 수정했으며 실패 보호 검사를 유지했다.
네이티브 입력 직후 검색 검사 1건은 revision이 반영되기 전에 호출했다.
입력 반영을 기다리도록 검사만 보완했고 20회 반복 및 최종 전체 검사에서 통과했다.
무관한 일정 대화상자 검사 1건의 시간 초과는 단독 재검과 최종 전체 607개 재검에서 통과했다.
초기 실패를 최종 통과 결과에 섞어 합산하지 않았다.
