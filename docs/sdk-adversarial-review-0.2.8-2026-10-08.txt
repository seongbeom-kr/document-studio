2. P2 SDK 닫기 확인창은 native 입력을 막지만 새 public execute 쓰기는 허용한다

사용자 및 통합 영향

standalone DocumentEditor에서 미저장 문서를 닫으려 하면 확인창이 열린다.
SDK는 이 동안 본문을 동결하지만 외부 에이전트/호스트가 public execute()로 보내는
새 쓰기는 받아들인다. 사용자에게 확인을 요구하는 동안 대상 상태가 다시 바뀔 수 있다.
이후 '변경 버리고 닫기'를 선택하면 확인창을 띄운 뒤 들어온 편집도 함께 버리게 된다.

재현 시험

실제 DocumentEditor 컴포넌트와 SessionStore를 사용했다.
native codec/렌더러는 쓰기 호출·revision과 입력 잠금 상태를 관찰하는 시험 대역이다.

1) 준비된 문서에서 public execute(insertText)로 첫 변경을 만든다.
2) standalone 헤더의 닫기를 누른다.
3) '편집을 마칠까요?' dialog가 열리고 setInputBlocked(true)가 호출된 것을 확인한다.
4) 그 상태에서 public execute(insertText)로 새 명령을 보낸다.
5) Promise가 거절되지 않고 완료된다. '거절되어야 한다'는 새 경계 시험이 실패한다.

대조 시험은 acquireInputLock()을 명시적으로 확보했을 때 같은 쓰기가 거절되고,
release 후 다시 편집할 수 있음을 확인했으며 통과했다.
따라서 새 입력 잠금 기능 전체가 작동하지 않는다는 발견이 아니다.
모달 상태가 public 쓰기 가드에 포함되지 않는 것이 문제다.

syncInputBlock은 busy, inputLocks, modalBlocked, readOnly를 모두 포함해 native 입력을 막는다.

같은 파일 523행의 execute 가드는 readOnly와 inputLocks만 확인한다.

수정 방향

신규 쓰기의 공통 가드를 만들고 execute/replace/applyPreset/agent bridge 경로에 적용한다.
UI/native 동결 사유와 public mutation 거절 사유가 서로 달라지지 않게 한다.
잠금 이전에 수락한 명령을 마지막 저장에서 drain하는 동작은 유지해야 한다.
확인창을 닫고 계속 편집할 때는 새 쓰기가 다시 가능해야 한다.

범위 한정

이 발견은 SDK standalone 닫기 확인과 programmatic 쓰기를 함께 사용하는 조건이다.
실제 샌드박스의 '저장 후 닫기'에서 새 입력 유실을 이번에 재현한 것은 아니다.
기존 0.2.7의 HWPX readonly 문제를 다시 재현한 결과로 표현하지 않는다.
native DOCX/HWPX 엔진에서 이 모달 경로를 강제로 호출한 브라우저 시험도 수행하지 않았다.

5. 검토한 방어와 남는 유지보수 부담

좋은 방어
- agent bridge의 documentId/sessionId/version/revision 확인 및 비동기 완료 후 대상 재검증.
- 저장 시 입력 동결, 선행 명령 drain, 원본 버전 확인, 저장 성공과 후속 처리 실패의 구분.
- 검색 요청 세대와 revision에 묶인 결과/치환 대상. 기존 재현 시험 통과.
- ZIP 크기/항목 수/실제 압축 해제량/CRC 및 엔트리 구조 검사.
- 이미지 헤더를 먼저 읽는 크기 제한과 애니메이션 프레임 관련 방어.
- RHWP message origin과 source window 확인.
- 고정 native patch의 해시/대상 유일성 검사 및 적용되지 않은 빌드의 실패 처리.

이 항목은 코드 검토와 기존 단위 시험 범위의 평가다.
모든 악성 파일, 모든 native 렌더러 오류, 모든 업무 문서 호환성을 증명하는 보안 인증은 아니다.

후속 개선
- 입력 동결, 모달, 저장, 전환, 권한을 여러 가드가 각각 판정한다. 이번 P2처럼 판정이
  어긋나지 않도록 공통 쓰기 정책과 상태 전이를 분리해 검증하는 것이 좋다.
- 외부 engine 구현자에게 setInputBlocked의 의미, 잠금 완료 응답, 진행 중 조합 입력 처리,
  잠금 이전 명령 drain 계약을 문서화해야 한다. built-in 엔진 시험만으로 외부 엔진을 보장할 수 없다.
- native minified paint 패치는 버전 고정으로 방어하지만 업그레이드 때 의도·해시·화면 QA를
  함께 갱신해야 한다. 단순 dependency bump로 처리하지 않는 검증 절차가 필요하다.

실제 시험은 자체 검증용 DOCX/HWPX 두 파일만 수정했다.
이번 시험의 문장 변경은 원래 내용으로 복구했으며, 실제 저장 때문에 revision은 증가할 수 있다.
다른 작업 파일이나 사용자 대화를 수정하지 않았다.
Windows 물리 IME 조합 입력, 최신 Word/한컴 native 호환성, 오프라인/다중 브라우저 경합은
이번에 새로 수용 검증한 범위가 아니다.

수정 우선순위

첫째, 실제 새 문서 생성의 lease/업로드 계약을 맞춘다.
둘째, 모달과 public SDK 쓰기의 잠금 판정을 통일한다.
셋째, 실제 서버 정책을 포함한 생성 수용 시험을 gate로 추가한다.
단위 시험 개수를 늘리는 것보다, 현재 빠진 경계 계약을 정확히 시험하는 것이 우선이다.
