결과

SDK와 샌드박스 연결 코드를 수정하고 네 SDK 패키지를 0.2.7로 반영했다.
샌드박스와 settings를 함께 재기동했으며 public health와 설정 SSE 연결을 확인했다.
GitHub/npm 공개 게시와 운영 배포는 수행하지 않았다.
인증된 실제 워크스페이스의 새 파일 저장·편집 잠금 전환은 직접 재검증하지 못했다.
저장된 브라우저 접근 제한 때문에 해당 주소에 인증 정보를 주입하거나 우회하지 않았다.

1. 새 문서 생성 연결: 프론트 수정

- DocumentEditor.onCreateDocument를 샌드박스 워크스페이스 업로드에 연결했다.
- 현재 편집본 저장 → 새 파일 업로드 → 반영 확인 → 목록 갱신 → 마지막 편집 저장과
  기존 lease 해제 → 생성 파일 편집으로 전환한다. 업로드 중 추가 입력도 마지막 저장에서 반영한다.
- 현재 문서와 같은 폴더에 새 이름으로 만들며 overwrite=false 업로드 경로를 사용한다.
- 생성/저장/업로드/목록 갱신/전환 실패 시 기존 편집기를 유지한다.
- 업로드 완료와 후속 반영·열기 완료를 구분한다. 재시도 때 이미 저장한 파일을 재업로드하지 않는다.
- 완료 응답을 잃었을 때에는 호스트 파일 목록의 digest로 저장 여부를 확인한다.
  반영 재시도에는 기존 /files/deliver API를 사용한다. 역방향 전체 sync를 대신 호출하지 않는다.
- /files/refresh의 synced=false는 '이번 호출에서 복사한 변경 없음'일 수 있다.
  동기화 실패로 해석하지 않고, 저장 digest와 명시적 delivery 응답을 검증한다.
- 문서·사용자·세션·lease·권한 변경과 unmount 이후의 늦은 응답을 차단하고 요청을 취소한다.

2. 자동화 입력 보존: SDK 수정

- 문서의 현재 편집 세션에 AutomationSession을 두고 기능별 입력·추가 인수·셀 변환·열 구분을 보관한다.
- 기능 전환, 속성 탭 전환, 도구 닫기/재열기에서 입력을 유지한다. 다른 문서나 새 편집 세션에는 전달하지 않는다.
- 기본 예제는 최초 진입과 '예제로 초기화'에만 채운다. 기능 전환 시 결과 미리보기는 무효화한다.
- 이 폼 상태는 메모리에만 보관한다. 서버/브라우저 저장소에 추가 기록하지 않는다.
- 같은 미리보기의 생성 콜백 실패 후 재시도에는 같은 생성 문서 ID를 유지한다.
- 생성 중 새 원본이 로딩되거나 권한·콜백 제공 여부가 바뀌면 이전 요청의 콜백을 취소한다.
  권한을 잠깐 해제했다 복구해도 이전 생성 작업은 계속 진행하지 않는다.
- 새 문서 저장을 연결하지 않은 호스트에는 미지원 이유를 안내한다.

3. 그림 배치 재판정과 추가 결함 수정: SDK의 DOCX 렌더러 수정

리뷰의 원본 docx-with-image.docx를 그대로 검사했다.
제목 첫 글자 '공', 80x20mm 그림, '개 ...'는 같은 기준선의 인라인 배치였다.
그림과 양옆 텍스트의 세로 좌표는 겹치지만, 두 축의 사각형은 실제로 겹치지 않았다.
Microsoft Word에서도 같은 줄 배치·크기·가로 비중첩을 확인했다.
이 원본 사례를 제목 글자가 그림에 덮이는 결함으로 확정하지 않았다.

확장 시험에서 별도의 실제 결함을 발견했다.
표 셀의 줄이 그림으로 시작하면 첫 텍스트의 시작 좌표에 그림 너비가 다시 더해져,
그림 오른쪽 723.50px에서 시작해야 할 글자가 1025.86px로 밀려 셀에서 잘렸다.

고정 EigenPal 2.25.0의 native paint를 보정했다.
- paint의 시작 좌표는 첫 텍스트만이 아니라 선행 그림 atom의 advanceStart까지 포함한다.
- fragment 안에서는 보정된 시작 좌표를 다시 원래 값으로 덮어쓰지 않는다.
- shaped text cursor에는 그림 spacer의 advance도 포함한다.
- 문서 XML, 그림 크기, native layout의 span/drawing geometry는 변경하지 않는다.
- CSS overlay나 소비 앱의 node_modules 수동 변경을 사용하지 않는다.

scripts/docx-paint-patch.mjs가 원본 chunk SHA-256과 변경 지점의 유일성을 검증한다.
engine-docx tarball은 보정된 무료 core/react/i18n 코드를 번들한다.
소비 앱은 별도 patch 설정을 적용할 필요가 없다.
원본 commit/path와 변경 사실은 NOTICE 및 dist/native-patch.json에 기록했다.
Apache-2.0 및 기존 라이선스/고지를 유지했으며 Pro/editor-api는 포함하지 않는다.

원본 코드: https://github.com/eigenpal/docx-editor/blob/ff8242b025c8487c2309027ac65d7e51a14be7f4/packages/core/src/output/semantic-paint.ts

검증 한계와 유지되는 제한

- 자체 합성 fixture 중심이며 실제 업무 문서 전체의 호환성을 보장하지 않는다.
- 한컴 native 프로그램 및 물리 Windows IME는 이번에 시험하지 않았다.
- Word는 크기·줄 위치·가로 좌표·문서 구조를 검사했다. 픽셀 동일 시각 비교는 아니다.

  모의 API·실제 SDK 시험과 public health/SSE를 그 시험의 통과로 대체하지 않는다.
- 고정 DOCX 엔진은 표 셀의 단일 텍스트 segment 중간 그림 삽입을 거절할 수 있다.
  문단 처음/끝 등 허용되는 경계에서의 삽입을 검사했으며 제한을 기능 지원표에 기록했다.
