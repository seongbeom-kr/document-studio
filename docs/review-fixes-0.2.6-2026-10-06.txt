수정 계획과 결과
1. 서식 묶음을 엔진의 하나의 편집 작업으로 실행한다.
   DOCX는 공개 canonical transaction API로 먼저 변경을 계획하고 한 번에 적용한다.
   HWPX는 고정 MIT 소스의 JS 이력을 SDK 빌드 플러그인으로 확장한다. 바깥 native
   SnapshotCommand가 내용 롤백과 한 번 Undo/Redo를 맡고 안쪽 명령의 별도 이력은
   보관하지 않는다. upstream 원본 소스 파일과 Rust/WASM은 수정하지 않았다.
   커서 입력 대기 서식도 복구한다. 실행 직전 세션·권한·원본·revision 검사와
   지원/값 검증을 유지한다. 연결 오류로 결과가 불확실한 경우 상태 확인을 안내한다.
   executePreset이 없는 외부 엔진은 기존 순차 fallback과 단계별 복구 안내를 유지한다.
   DOCX의 사용되지 않는 목록 정의가 Undo 뒤 남는 native 동작은 문서 내용 복구와 구분한다.

2. 수치는 소수 둘째 자리까지 표시하고 원래 내부 수치를 보존한다.
   혼합/미확인 값에 설명을 연결하고, 직접 수정한 문단 속성만 적용한다.
   변경 없는 페이지/문단 적용은 비활성화한다. 원래 값으로 돌아간 변경도 정리한다.

3. 업무 자동화 20종의 입력을 기능별 이름·예시·기본값·검증으로 교체한다.
   기준일, 취합 시작 행, 조직 순서, 차트 종류, 추첨 인원, 조 수 등을 구분한다.
   탭/CSV 자동 감지와 명시적 구분 선택을 제공한다. 취합 시작 행은 1부터 센다.
   오류 뒤 이전 결과를 남기지 않으며 좁은 패널은 입력과 결과를 세로로 배치한다.
   에이전트도 listAutomationForms()로 같은 입력 계약을 조회한다.

4. 그림의 원본 비율 유지, 본문 폭 맞춤, 삽입 위치 안내를 제공한다.
   표시 반올림과 실제 크기를 분리하고 PNG/JPEG/GIF 해제 화소를 사전 검사한다.
   파일 8 MiB, 한 변 32,768px, 전체 4,000만 화소 제한을 적용한다.
   GIF의 누적 프레임도 검사한다. 문서 전환 중 늦게 읽힌 그림은 버린다.

5. 자체 제작 복합 corpus의 편집·저장·재열기 및 Word native 검사를 추가한다.
   표, 병합 셀, 그림, 머리말·꼬리말, DATE 필드와 각주를 포함한다.
   미디어 bytes, 비대상 XML, 문서 텍스트/문단 수를 검사한다.
   최초 XML 직렬화의 정규화와 ZIP 디렉터리 항목 제거를 콘텐츠 손실로 세지 않는다.

실패 시도와 수정 내역
초기 native DOCX 시험의 fixture URL과 빈 Undo 가정을 바로잡았다.
복합 fixture의 중복 OPC 메타데이터와 누락된 xml:space를 native Word 검사로 발견해
생성기를 고쳤다. 이전 결과와 수정 내역은 corpus-amendment.json에 보존했다.
최초 프론트 전체는 동시 작업 부하 중 관련 없는 일정 관리 시험 2개가 10초 제한에 걸렸다.

최초 혼합 E2E는 Chrome 시험 완료 후 브라우저 전환이 멈춰 중단했고, 각 브라우저의
전체 실행과 원래 로그를 별도로 보존했다. 이를 단일 혼합 실행의 성공으로 표시하지 않는다.
