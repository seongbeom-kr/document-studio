Document Studio 0.2.22 — 범피스 참고 기능 구현·검증
작성일: 2026-10-16

구현 범위
1. 빠른 작업: 오늘/어제/내일, 주간·월간·연간 기간, 기존 보고서/호스트 서식.
   기준일·주간 범위·대상·결과를 미리 확인하며 UI와 agent가 동일 API를 사용한다.
2. 기존 표의 선택한 열: 접두사·접미사·앞뒤 공백·연속 공백 정리를 추가했다.
   기존 쉼표/치환의 변경·제외 미리보기, 사번/날짜 보호, 한 번 Undo 계약을 유지한다.
3. 사용자 서식: DOCX/HWPX 텍스트 필드와 CSV/TSV 열 매핑, 전체 출력 미리보기,
   배치 생성/취소/ZIP 다운로드. 원본을 유지하고 전체 성공한 사본만 공개한다.
   생성은 서버 저장이 아니다. 최대 20개이며 등록 서식과 결과 bytes는 세션 메모리에 보관한다.

자료 및 라이선스
- 사용자가 제공한 범피스 실제 사용 보고서 3쪽과 현재 SDK 기능을 비교했다.
- 보고서의 실제 성공 5항목과 메뉴/코드 관찰·시험 미완료를 구분했다.
- 범피스 바이너리·코드·이미지·기관 서식을 배포물에 복사하지 않았다.
- 새 런타임 의존성 없이 자체 Apache-2.0 코드로 구현했다.
- 라이선스 gate 통과: npm 105개, 고정 Rust registry crate 393개.
- production dependency audit: 보고 항목 없음. 개별 업무 문서의 이용 권한까지 검사하는 것은 아니다.

초기 실패와 수정
- HWPX에서 선택 문자열을 날짜로 교체하면 삭제/삽입이 두 Undo로 분리됐다.
  native history 그룹에 텍스트 삽입 경로를 추가해 한 번 Undo/Redo와 저장·재열기로 확인했다.
- 시험용 1×1 PNG 데이터가 정상 이미지가 아니어서 8×8 정상 PNG fixture로 수정했다.
- 생성 파일을 현재 편집기의 미저장 문서 위에 바로 열려던 시험은 정상 전환 가드에 차단됐다.
  별도 편집기에 생성 사본을 재열어 원본 보존과 사본 내용을 동시에 확인하도록 고쳤다.
- 상태 observer가 예외를 던져도 완료한 생성 결과를 실패로 바꾸지 않도록 알림 오류를 격리했다.
- 병렬 Playwright 작업의 출력 폴더 충돌은 각 작업의 --output 경로를 분리해 재검증했다.
