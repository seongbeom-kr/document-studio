Document Studio SDK 0.2.31 수정 및 검증
작업일: 2026-10-20
범위: document-studio SDK, 독립 예제/소비 앱, SDK 문서와 회귀 시험.
프론트·General 소스 및 서비스 설정 변경 없음.

1. HWPX 초기화
제어 Chrome의 독립 프로덕션 SDK에서 최초 열기는 성공했지만 재열기에서
iframe-loading / frame-attached만 남는 30초 실패를 재현했다.
별도 로컬 정적 서버는 HTML 200 응답을 완료했지만 브라우저는 boot 스크립트를 요청하지 않았다.
SDK 없이 HWPX iframe을 다시 열면 스크립트 실행과 편집 화면 표시가 확인됐고, 검증 Worker 종료 직후
iframe을 생성하는 최소 대조에서 같은 멈춤을 재현했다.
Worker를 종료한 뒤 다음 이벤트 루프 작업에서 연결한 대조는 최초+재열기 5회 통과했다.
이는 해당 제어 환경에서의 재현/완화 근거이며 브라우저 내부 결함 원인까지 확정한 것은 아니다.

runValidationWorker는 성공 응답에서 Worker 핸들러를 해제하고 종료한 뒤,
다음 작업에서 성공을 전달한다. 그 사이 AbortSignal 취소는 성공 전달을 막는다.
오류·시간 제한은 유지하고 자동 재시도나 타임아웃 증가를 넣지 않았다.
실제 수정 SDK에서도 제어 Chrome 첫 열기+재열기 4회가 수동 재시도 없이 통과했다.
로딩 단계·경과 시간·원본 유지 상태를 표시하고 성공 시도 진단도 보관한다.
운영 샌드박스의 새 SDK 연결 재검증은 이번 SDK 전용 범위 밖이다.

2. 선택 영역 질문
DOCX·HWPX에서 한 단락 안의 부분 선택을 원래 텍스트/논리 위치 그대로 전달한다.
선택이 접혀 있으면 기존처럼 단락 전체를 지정한다.
입력창은 선택 위치에 붙고 확대·스크롤·좁은 호스트를 따라 배치된다.
선택이 화면 밖이면 입력을 보존하고 안내하며, 다시 보이면 재연결한다.
문서/세션/version/revision/선택 변경은 전송을 차단한다.
Escape 취소와 전송 완료 후 열기 버튼 포커스 복귀, 한국어 조합 중 Escape 보호를 포함한다.
HWPX 표·그림 및 여러 단락에 걸친 질문은 아직 지원하지 않는다.
모델 호출과 승인된 문서 적용은 호스트 콜백/기존 편집 경로의 책임이다.

3. 표 읽기 오류
TableReadError를 추가하여 선택 없음, 표 밖, 지원하지 않는 구조, 크기 제한을 구분한다.
effect=none, retryable=false, code와 requiredAction을 제공한다.
기존 TableEditError 상속으로 소비 앱과의 오류 처리 호환성을 유지한다.
HWPX 확장→RPC→SDK에서 오류 원인을 보존한다.

4. 에이전트 도구
createAgentToolset는 메서드별 스키마/설명을 제공하는 선택형 공통 도구 10개를 노출한다.
추가 인수·잘못된 중첩 입력을 실행 전에 거절하고 해당 입력 스키마를 제공한다.
getContext는 전체 서식 명령 목록 대신 기본 식별자·revision·준비 상태를 제공한다.
기존 쓰기 가드·표 미리보기·저장 영수증/operationId 처리 경로를 사용한다.
특정 모델 또는 General 연결은 추가하지 않았다. 실제 모델의 왕복/지연 개선은 미측정이다.

5. 작은 UI 수정
HWPX 서식 재등록 전에도 현재 문서 형식에 맞는 출력 파일명 예시를 표시한다.
호스트의 CSV 읽기 연결, 채팅 결과 카드, 서버 다운로드 파일명 정책은 변경하지 않았다.

최종 검증
- 단위 테스트: 31개 파일, 490개 통과.
- 타입 검사, SDK 빌드, 플레이그라운드 빌드, yarn install --immutable: 통과.
- 라이선스 검사: npm 105개·고정 Rust crate 393개 통과. 보안 audit: exit 0.
- 별도 npm tarball 설치/Next.js 프로덕션 빌드 통과. Next.js 브라우저 4조합,
  일반 JS·Vue 브라우저/형식 8조합 통과.
- 최초 전체 브라우저 실행: 1,051개 통과, 1개 실패. 실패는 재열기 직후 이전
  ready 값을 읽은 시험 대기 조건이었다. SDK는 교차 세션 조회를 올바르게 거부했다.
- 새 세션 ID와 ready를 함께 기다리도록 시험만 수정. 초기화 전체 22사례를
  Chrome·Edge에서 각각 3회씩 실행한 66회 재검증 모두 통과.
- 이모지·결합 문자·사번·동일 문구의 두 번째 선택·전송 후 포커스 회귀 4개 추가 통과.
- 재검증을 반영한 서로 다른 최종 사례: 1,056개(Chrome 528, Edge 528), 미해결 실패 0.
  66회 반복을 서로 다른 사례 수에 중복 가산하지 않았다.
- 제어 Chrome의 실제 SDK: 첫 열기+재열기 4회, 수동 재시도 없이 통과.
- 운영 샌드박스/실제 모델·General 저장, 물리 IME, 실제 Word/한컴 열기는 이번에 수행하지 않았다.
  SDK를 소비하는 프론트·General 변경/푸시/로그인 변경 없음.

전체 실행 원본·첫 실패 trace를 보존했고 verification-summary.json에 재검증 구분을 기록했다.
검증 종료 후 직접 연 브라우저 탭과 임시 서버를 정리한다.
