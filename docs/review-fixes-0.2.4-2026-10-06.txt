수정
1. 비동기 명령 중 저장 후 종료
SDK가 pendingCommands와 busy에 실행 중 명령을 노출한다. save({ onlyIfDirty: true })는
새 입력을 잠그고 기존 명령/초안 내보내기가 끝난 뒤 변경 여부를 판단한다.
명령/내보내기 실패나 세션 변경은 저장을 거부하고 편집기를 유지한다.
진행 중 저장에 대한 중복 호출은 같은 Promise를 기다리고 업로드를 한 번 수행한다.
프론트는 종료/파일 이동/미리보기/요청 전달 경로에서 이 저장 장벽을 기다린다.
저장 후 세션, 경로, 권한, dirty와 동기화 경고를 확인한 뒤 종료한다.
미변경 문서는 업로드를 생략하고, 진행 중 명령에는 beforeunload 보호를 적용한다.

2. 자기 저장의 동일 버전 원본 갱신
SDK가 승인된 저장의 문서 ID/형식/세션/초안 namespace/버전/바이트 복사본을 보관한다.
동일 digest와 새 Uint8Array로 돌아오는 자기 저장도 내용이 일치하면 수용한다.
서로 다른 바이트, 문서, 세션, namespace, 버전은 이 승인으로 허용하지 않는다.
내용을 Undo로 되돌린 뒤 같은 digest 저장 → 추가 편집 → 재저장을 회귀 검증한다.

3. UI/UX
편집 시작 시 원래 패널 크기를 유지한다. '크게 보기'로 수동 확대한다.
1100px 이하의 편집기에서는 속성 도구를 아래에 배치해 문서 폭을 유지한다.
확대 선택의 '페이지 너비에 맞춤'은 실제 쪽 폭과 문서 가시 영역의 크기를 관찰해
배율을 계산한다. 수동 배율로 돌아가면 자동 맞춤을 종료한다.
도구 이름은 '문단·표·그림', '삽입·쪽 메뉴'로 명확히 하고 종료는 '저장 후 닫기'로 표시한다.
일반 도움말은 접고, 작업 결과에는 '직전 작업'을 표시해 Undo 뒤 현재 상태와 구분한다.
