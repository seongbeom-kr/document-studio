1. 결론

현재 개발자 샌드박스 주소는 정상으로 열린다. 이전 404는 이번 확인 시 나타나지 않았다.
실제 화면의 data-document-studio-version은 0.2.2였다.
검색, 모두 바꾸기, 되돌리기, 반응형 전환, 저장 및 재열기를 직접 시험했다.

새로 확인한 문제는 DOCX 일괄 치환의 되돌리기 단위, 화면 폭 변경 후 파일 목록 복귀,
변경 없는 문서의 떠나기 경고 요청이다. 앞의 두 항목은 실제 브라우저에서,
마지막 항목은 실제 컴포넌트를 실행하는 시험에서 재현했다.

기존 적대적 리뷰의 P1 3건과 조건부 P2 1건 관련 소스 파일은 SHA-256 비교 결과
모두 이전과 동일했다. UI가 정상으로 열리는 것을 그 코드 문제의 해결로 보지 않는다.

2. 이번에 확인한 문제

[P2] DOCX '모두 바꾸기'가 한 번의 되돌리기로 취소되지 않는다

위치:
D:\dev\document-studio\packages\engine-docx\src\docx-view.tsx:284-289

재현:
시험 DOCX에서 '확인'을 검색하면 3개 결과가 나왔다.
'모두 바꾸기'로 '검토'로 바꾸면 3개가 모두 바뀌었다.
되돌리기를 한 번 누르자 한 곳만 원래대로 돌아오고 두 곳은 '검토'로 남았다.
총 세 번 되돌리기를 해야 원래 텍스트와 일치했다.

원인:
각 검색 결과에 대해 editor.exec(replacementCommand())를 개별 실행한다.
사용자에게는 한 번의 '모두 바꾸기'이지만 여러 개의 undo 작업으로 쌓인다.

형식 간 비교:
HWPX에서도 같은 세 곳을 바꿨다. 한 번의 되돌리기 후 '검토' 검색은 0개,
'확인' 검색은 3개였다. HWPX는 일괄 작업 전체가 한 번에 취소됐다.
두 형식에서 같은 버튼의 되돌리기 의미가 달랐다.

영향:
사용자가 일괄 작업을 취소했다고 생각하고 저장하면 일부 변경만 남을 수 있다.
치환 대상이 많을수록 원상 복구를 위해 반복 조작해야 한다.

수정 방향:
모두 바꾸기를 하나의 undo transaction으로 묶는다.
엔진 API에서 묶음을 지원하지 않으면 snapshot/history 경계에서 명령 전체를 관리한다.
단일 치환과 일괄 치환의 되돌리기 동작을 두 형식에서 같은 기준으로 검증한다.

증거: 01-docx-partial-undo.png, 03-hwpx-undo-restored.png

범위:

[P2] 수정하지 않은 문서도 떠나기 경고 경로를 활성화한다

위치:
D:\dev\_worktrees\document-studio-ux-review-fixes\apps\sandbox-agent\app\_components\workspace\document-edit-session.tsx:226-232

재현:
실제 DocumentEditSession과 DocumentEditor를 실행했다.
엔진은 ready=true, dirty=false인 상태를 제공하도록 통제했다.
beforeunload 이벤트를 전달하자 defaultPrevented=true가 됐다.
기대값은 false였으며 추가 시험 1개가 이 조건에서 실패했다.

원인:
DocumentEditSession의 beforeunload handler는 dirty 여부와 관계없이
event.preventDefault()를 호출한다. SDK 자체의 dirty 조건부 경고와 별도로 동작한다.

영향:
수정하지 않았거나 이미 저장한 문서에서도 브라우저 조건에 따라 불필요한
떠나기 경고를 요청하게 된다. 경고의 신뢰성이 떨어진다.

수정 방향:
미저장 변경이나 진행 중인 저장 등 실제 보존할 작업이 있을 때만 경고한다.
변경 없는 문서의 lease 해제는 이미 있는 pagehide/unmount 경로로 처리한다.

재현 한계:
이번 항목은 jsdom에서 이벤트 취소 여부를 확인했다.
사용자 Chrome을 실제로 새로고침해 네이티브 경고창까지 띄우는 시험은 하지 않았다.

4. UI/UX 개선 우선순위

먼저, '사용자가 한 번 누른 명령 = 한 번 되돌리는 작업'이라는 규칙을 통일한다.
모두 바꾸기뿐 아니라 보고서 preset 등 여러 명령을 실행하는 기능도 이 기준으로 확인한다.

둘째, 돌아가기 동작이 표시한 목적지에 도착하도록 한다.
'파일 목록'은 화면 크기와 관계없이 파일 목록을 보여야 한다.
크게 보기/원래 크기와 파일 목록/편집 완료의 경로를 일관되게 유지한다.

셋째, 저장 상태와 경고를 정확하게 만든다.
'브라우저 초안 보관됨 / 작업 공간 저장 전 / 작업 공간 저장됨'을 구분한다.
수정이 없는 문서에는 손실 경고를 요청하지 않는다.
이 제안은 기존 P1 초안 보존 문제를 먼저 해결한 뒤 진행해야 한다.

넷째, 찾기 입력과 결과 맥락을 유지한다.
HWPX에서 찾기 패널을 닫았다가 Ctrl+F로 다시 열면 검색어와 바꿀 내용이 빈 칸으로 돌아왔다.
같은 문서를 편집하는 동안 마지막 검색어를 유지하고 다음/이전 결과로 쉽게 이동하게 한다.

다섯째, 속성 패널의 가독성과 기본 확대를 다듬는다.
라벨과 도움말 글자를 키우고 긴 라벨은 2열/전체 폭으로 정리한다.
사용자가 바꾸는 대상과 적용 범위를 표시하고 적용 버튼을 쉽게 찾게 한다.
넓은 화면에서는 '가로폭 맞춤 / 쪽 전체 보기'를 제공하면 100% 숫자만 선택하는 것보다 편하다.
종이 경계와 작업 배경을 두 형식에서 비슷하게 표현하는 방향이 좋다.
