# Document Studio 0.4.0

2026-11-01 · npm 패키지 및 소스

임의의 DOCX·HWPX 양식에서 작성 위치를 지정하고, 같은 정의로 보고서를 생성하는 기능을 추가합니다. 소비 서비스 반영은 각 앱의 잠금 파일 갱신과 기존 CI/CD를 통해 별도로 진행합니다.

## 변경 내용

- `@document-studio/template`: 원본 구조 검사, 선언형 항목·위치·규칙 검증, 사본 생성 및 결과 확인을 제공하는 공통 패키지입니다. 양식별 실행 스크립트는 필요하지 않습니다.
- `TemplateAuthoringEditor`: 읽기 전용 문서에서 문단·표 셀·일부 글자를 선택하고 기존 연결을 강조합니다. `createTemplateSelectionBridge`가 문서 식별자·원본 해시·revision·구조 주소와 선택 범위를 확인합니다.
- DOCX 단일 문장 교체 시 대상 글꼴·크기를 유지합니다.
- HWPX 긴 표 셀 교체와 읽기 전용 셀 재선택을 수정합니다. 실패 후 바이트 복구 여부를 확인해 작업 결과를 구분합니다.
- 어두운 호스트에서 확대 배율 선택기의 색 대비를 개선합니다.

## 소비 앱 갱신

core, react, engine-docx, engine-rhwp, browser, template 여섯 패키지를 같은 소스에서 `0.4.0`으로 생성합니다. React 호스트는 browser를 제외한 다섯 패키지를 함께 설치합니다. DOM 호스트는 browser도 설치합니다. 서버에서 양식만 처리하는 호스트는 template과 그 실행 계약을 사용합니다.

소비 앱은 tarball 해시·잠금 파일·HWPX 정적 자산을 함께 갱신해야 합니다. SDK GitHub 커밋만으로 이미 배포된 프론트 이미지가 바뀌지 않습니다. npm에서 정확한 버전을 설치하고 잠금 파일의 integrity로 검증합니다. 별도 SDK 서버는 필요하지 않습니다.

## 검증 범위와 한계

공개 API의 구조 주소·중복 문구·부분 범위·원본 교체 보호와 Chrome/Edge 편집 회귀를 확인했습니다. 합성 양식으로 실제 호스트의 모델 생성, DOCX·HWPX 수정, 서버 저장 영수증과 다운로드 해시 비교, 새 편집 세션 재열기를 확인했습니다. 초기 실패와 수동/자동 재시도는 최초 성공과 구분했습니다.

원본 전체 문서에 대한 같은 조판을 보증하지 않습니다. 복잡한 고객 문서, Word·한컴 데스크톱 재열기, 실제 초보 사용자 시험은 별도로 필요합니다. 일부 HWPX 개체·중첩 구조는 직접 위치 지정을 안전하게 거절할 수 있습니다. 호스트 인증 서버와 모델 제공자의 시간 초과도 SDK 기능 시험과 별도입니다.
